# Adversarial-Agent Plan — 2026-10-12

> Carries forward unfinished items from `docs/plan-2026-06-20.md`. The
> seed plan shipped four sources, a metadata-only quality scorer, a
> comparison harness, and offline CI. This plan attacks the follow-ups
> that plan explicitly deferred.

## Hypotheses under test

- **H2.** The seed `License` allowlist is the right *floor* but the wrong
  *ceiling* for yield. Adding the one explicitly ToS-permitted "paid-API"
  path from the project allowlist — **YouTube Data API with
  `videoLicense=creativeCommon`** restricted to **URL + metadata only, no
  media download** — materially increases license-clean yield without
  violating any hard constraint in `AGENTS.md`.
- **H3.** A *metadata-only* procedural-density signal (imperative-verb
  density on title + description + recipe steps) separates
  `cooking-adjacent` from `genuinely-procedural` cooking content better
  than the current `has_steps` boolean.
- **H4.** Multilingual expansion is cheap if a deterministic,
  offline-safe language detector exists; the current scorer silently
  concatenates languages and penalises nothing.
- **H5.** Two scrapers can both legitimately claim "I found N hours", yet
  disagree on *which* records matter. A deterministic `diff` of two
  `BenchmarkResult` payloads is required before we can talk about
  "progress" at all.
- **H6.** License classification is heuristic (seed plan risk #1).
  Downstream training must *never* consume a record whose license
  resolves to `UNKNOWN` or `RESTRICTED`. We should enforce this with an
  explicit filter that is covered by a dedicated test, not with
  implicit convention.

## Adversarial questions to attack today

1. **Yield.** Does the YouTube CC-only metadata channel measurably
   expand license-clean yield on the same `SourceQuery`? Produce a
   second `BenchmarkResult` row on the same fixtures so the delta is
   measurable, not asserted.
2. **Procedural density vs. has-steps.** Can we rank the existing
   fixture corpus more informatively with a continuous
   `procedural_density` signal than with the boolean `has_steps`?
3. **Multilingual readiness.** If `language_detected` becomes a field
   on `VideoRecord`, can we track per-language yield so a future
   adversarial plan can target under-represented languages?
4. **Comparability.** `specint diff old.json new.json` must produce a
   per-source delta table so any "we got better" claim is reproducible
   from committed artifacts.
5. **Safety.** Can we prove, with a test, that no `License.UNKNOWN`
   record ever reaches a training-eligibility selector?

## Concrete deliverables for `Coding-Agent`

- [ ] `src/specint/sources/youtube_cc.py` — YouTube Data API v3 adapter.
  `parse()` is pure and fixture-tested; `search()` requires
  `SPECINT_YOUTUBE_API_KEY`, enforces `videoLicense=creativeCommon`,
  and never writes a `media_url` (metadata-only; see allowlist).
- [ ] `src/specint/quality/language.py` — deterministic, offline
  function-word language detector for `{en, es, fr, de, it, pt}`.
  Returns `None` when confidence is below a documented threshold.
- [ ] `src/specint/quality/procedural.py` — imperative-verb density
  heuristic in `[0, 1]`, plus integration into
  `quality/metrics.py` as a new component with a documented weight.
- [ ] `src/specint/quality/safety.py` — `training_eligible(record)` plus
  `filter_for_training(iter)`. Rejects `License.UNKNOWN` and
  `License.RESTRICTED` unconditionally; test the invariant.
- [ ] `src/specint/compare/diff.py` + `specint diff a.json b.json` CLI
  subcommand. Output must be deterministic JSON suitable for CI
  diffing.
- [ ] `tests/fixtures/youtube_cc/search_cooking.json` — real-shaped but
  synthetic fixture (no scraping). Include at least one record that
  must be excluded (e.g. `license: youtube`) so negative-filter
  tests have teeth.
- [ ] `tests/test_sources_youtube_cc.py`, `tests/test_language.py`,
  `tests/test_procedural.py`, `tests/test_safety.py`,
  `tests/test_compare_diff.py`.
- [ ] New baseline `reports/baseline-2026-10-12.json` under the new
  scorer weights, with the YouTube fixture included. Document the
  delta vs. `reports/baseline-2026-06-20.json` in `plan.md`.

## Out of scope today

- Live YouTube API calls in CI (integration suite only; still gated on
  `SPECINT_RUN_INTEGRATION=1` *and* `SPECINT_YOUTUBE_API_KEY`).
- Non-Latin-script language detection (CJK, Arabic, etc.) — the simple
  function-word detector is explicitly scoped to Latin-script languages
  with easy stopword lists. CJK is a follow-up.
- Any actual YouTube media download. This remains explicitly forbidden
  by the project allowlist.

## Risks the next reviewer should challenge

- YouTube's `videoLicense=creativeCommon` filter has historically
  returned mislabelled records. The adapter must *verify* the
  per-video `status.license == "creativeCommon"` before emitting
  `License.CC_BY`; anything else falls through to `License.UNKNOWN`.
- The function-word detector is intentionally dumb; it will mis-detect
  heavily-mixed-language descriptions. Documenting its confidence
  threshold is the mitigation.
- Reweighting the quality scorer invalidates numeric comparability
  with the 2026-06-20 baseline. Both baselines must stay in `reports/`
  and the `plan.md` entry must call out the regression surface.
