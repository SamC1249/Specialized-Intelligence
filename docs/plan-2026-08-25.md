# Adversarial-Agent Plan — 2026-08-25

> Two months since the seed plan (`plan-2026-06-20.md`). This one is an
> **attack pass**: what's actually broken, missing, or unfalsifiable in
> the current pipeline, plus the highest-leverage additions we can
> justify under AGENTS.md's constraints.

## TL;DR — what the next Coding-Agent PRs must ship

1. **Fix a live violation of AGENTS.md rule #2.** `Provenance.extractor_git`
   defaults to `"dev"` everywhere. AGENTS.md explicitly requires "the
   exact extractor commit hash" on every record. Today's PR lands a
   `specint.provenance.resolve_extractor_git()` helper and wires it into
   every adapter, plus a unit test that asserts records emitted in a
   git working tree carry a non-`"dev"` SHA.
2. **Regression-lock the fixture baseline.** AGENTS.md rule #3 says
   improvements must be measured. Today's PR adds
   `tests/test_regression_baseline.py`, which reruns the harness against
   the checked-in fixtures and asserts each per-source `mean_quality`
   and `n_records` are within tolerance of
   `reports/baseline-2026-06-20.json`. Any future PR that "improves"
   quality scoring must beat the baseline explicitly, not silently.
3. **Ban live network in unit tests.** AGENTS.md rule #4. Today's PR
   ships an autouse pytest fixture that raises on outbound
   `httpx.Client.send`, so accidental live HTTP in a unit test fails CI
   deterministically. A single test proves the guard actually fires.

## Weaknesses I identified (adversarial pass)

### W1. Provenance is a lie by default. **(fixed today.)**

`Provenance.extractor_git: str = "dev"`. Every fixture-parsed record
today carries `"dev"`, and every future live crawl will too if the
adapter forgets to pass the SHA in. This directly violates AGENTS.md
rule #2 ("Every record must carry ... the exact extractor commit
hash"). Mitigation: `resolve_extractor_git()` reads `.git/HEAD` (and
follows a ref if it points to one), falls back to `SPECINT_GIT_SHA`
env var (for CI/containers), and only then to `"dev"`.

### W2. Baselines can silently regress. **(fixed today.)**

The 2026-06-20 baseline was committed but nothing in CI compares
future runs against it. A refactor of the quality scorer or the license
matcher could tank yield with green tests. The new regression test
closes this by asserting `n_records`, `n_license_clean`, and
`mean_quality` per source against the checked-in JSON with a small
absolute tolerance (`1e-3` on floats, exact on ints).

### W3. Unit tests can silently start hitting the network. **(fixed today.)**

The seed suite is offline *by convention*, not by construction. A new
adapter could smuggle a real `httpx.get()` into a helper and CI would
happily hit the internet, invalidating rule #4. New autouse fixture
patches `httpx.Client.send` to raise unless a test opts in with the
existing `@pytest.mark.integration` marker.

### W4. Duration score is tuned for the wrong horizon.

`_score_duration` peaks at 300s and decays to zero by ~1 hour. But the
research payload we actually want for world-model training is the
**long-horizon, multi-step, irreversible** segment — CaptainCook4D's
average recording is 8–12 minutes, ProMQA cooking videos likewise, and
VideoAuteur's ICCV'25 corpus is explicitly *long-form*. Our peak is
below their median. **Coding-Agent should:** replace the current
piecewise linear with a log-normal-shaped curve peaking around
8–12 min (600s), decaying gently out to 45 min. Ship it as a new
component under a feature flag, run the harness under both,
commit the diff to `reports/`, and only then flip the default.

### W5. License classification is duplicated per adapter.

`wikimedia._coerce_license`, `archive_org._license_from_url`, and (via
enum) `peertube._peertube_license` all reimplement license inference.
No single test asserts adversarial cases like
`"Attribution-NonCommercial-ShareAlike 4.0 International"`,
`"CC-BY-4.0"`, `"cc0-1.0"`, or the various Public Domain Mark strings.
**Coding-Agent should:** extract a `specint.licenses` module with a
canonical `classify(text: str | None, url: str | None) -> License`
plus a table-driven pytest matrix of ≥30 real-world license strings.

### W6. No cross-source deduplication.

The same Blender cooking short might live on Wikimedia Commons, three
PeerTube instances, and Internet Archive. Currently our aggregate
`n_records` triple-counts it. **Coding-Agent should:** add a
`specint.dedup` module. Phase 1 (metadata only): SHA1 over
`(normalized_title, floor(duration_s), author_normalized)` and
title-Jaccard over shingles. Phase 2 (when we start pulling media):
port `videohash`-style perceptual hashing (arXiv 2606.12215 MLT-Dedup
is overkill for our scale; a wavelet-hash collage per video is fine).
Add a `n_duplicates_removed` field to `BenchmarkResult`.

### W7. `CommonCrawlRecipeSource.search` is a stub.

The parser works on a fixture, but `search()` returns `[]`. Live yield
is zero. Two legitimate paths without violating our allowlist:
- **Web Data Commons schema.org corpus** (see
  `docs/artifacts/web-data-commons.md`). WDC re-processes Common Crawl
  and publishes JSON-LD/Microdata extracts by class (`VideoObject`,
  `Recipe`) as RDF quads. Point at those instead of raw WARCs.
- **CDX + selective fetch**: use Common Crawl's CDX index to enumerate
  URLs matching known recipe hosts, then only fetch pages where the
  host has a permissive site-wide license (`wikibooks.org`,
  `wikimedia.org` recipe books, `simplyrecipes.com` — no, that's ARR;
  keep the whitelist tiny and defensible).

Coding-Agent should ship the WDC-corpus path first because the license
provenance is entirely at the *host* level, not the JSON-LD-embedded
`contentUrl` (which the seed plan already warned lies).

### W8. Source allowlist under-uses free, legitimate corpora.

Concrete additions to propose (each has its own artifact note under
`docs/artifacts/`):

- **TIB AV Portal** (CC0 metadata, mostly CC-BY / CC-BY-SA video, OAI-PMH
  + RDF dump). Scientific — not cooking — but critical for the
  "difficult video, adjacent domain" generalization goal AGENTS.md
  calls out (lab work, experiments).
- **FineVideo (HuggingFaceFV/finevideo)** — 43k CC-BY YouTube videos
  aggregated from **YouTube-Commons**, with time-coded transcripts.
  This is the model to follow for our own YouTube CC harvester (which
  AGENTS.md already allows: `videoLicense=creativeCommon` metadata
  only). Adds a natural benchmark vs. our own yield.
- **OpenVid-1M / VideoUFO** — CC-BY-4.0. Both are already-packaged;
  they belong in the *comparison* target list (we want to prove our
  method finds videos they didn't) rather than as a source to
  re-scrape.

### W9. Yield/quality is not decomposed by domain.

Right now the harness reports one aggregate quality number. But
"cooking" and "surgery" and "manufacturing" will have very different
optimal duration/text-density priors. **Coding-Agent should:** make
`SourceQuery` carry a `domain: str` field and let quality components
opt into per-domain calibration (starting with duration curve).

### W10. No YouTube CC adapter.

AGENTS.md explicitly permits YouTube Data API with
`videoLicense=creativeCommon` for URL + metadata only. This is the
single largest unclaimed yield in the allowlist. **Coding-Agent
should:** add `src/specint/sources/youtube_cc.py` with a `parse` that
consumes the exact JSON shape of `search.list?videoLicense=creativeCommon`
plus `videos.list?part=contentDetails,snippet,status`. Fixture and unit
test only — live `search()` gated on `YOUTUBE_API_KEY` and
`SPECINT_RUN_INTEGRATION=1`.

## Hypotheses to test in follow-up PRs

- **H2.** Domain-calibrated duration scoring materially reshuffles the
  per-source ranking. Metric: kendall-tau between old and new
  per-source `mean_quality` rankings across ≥3 fixture domains.
- **H3.** Cross-source dedup removes ≥15% of aggregate records once
  YouTube-CC and Wikimedia are both live (Wikimedia mirrors many
  Blender Institute cooking demos).
- **H4.** WDC schema.org VideoObject yields ≥10× the license-clean
  recipe URLs vs. our current stub, but only ≤30% of them are
  page-license-clean once we require a permissive host.
- **H5.** A metadata-only, procedural-density heuristic (recipe steps
  present + imperative-verb ratio in title/description) is a better
  downstream-usefulness predictor for cooking than resolution alone.
  Measure by correlation with a small hand-labelled 30-video pilot.

## Risks the next Adversarial-Agent should attack

- **Git SHA in ephemeral containers.** `resolve_extractor_git()` reads
  `.git/HEAD`; in a stripped Docker image with no `.git`, we'll fall
  back to `SPECINT_GIT_SHA` and then `"dev"`. Verify the deploy path
  actually sets the env var. Consider baking the SHA into the wheel at
  build time via `setuptools_scm`.
- **Regression test is fixture-locked.** If someone edits a fixture,
  the test happily locks the new (possibly worse) numbers. Follow-up:
  hash fixtures and refuse to update the baseline without a doc entry
  explaining why.
- **Network guard vs. legitimate mocks.** If Coding-Agent starts using
  `respx` or `httpx.MockTransport`, the guard needs a per-test
  opt-out. Today only `@pytest.mark.integration` opts out.
