## Adversarial attacks on the current baseline

I intentionally treat the June baseline as *hostilely* as possible.

### Attack A — the baseline double-counts

Two sources returning the *same* video (Wikimedia mirrored on
Archive.org; a Common Crawl page that embeds a PeerTube URL) will each
count as +1 record and +duration in the aggregate row. Every "yield"
number we quote is therefore biased up by an unknown factor. Nothing
in the current pipeline detects cross-source duplicates.

**Hypothesis H1.** After adding a cross-source deduplicator, the
`__total__` row's `n_unique_across_sources` is strictly less than
`n_records`. On our current fixtures the drop is small (fixtures were
authored independently). On any live corpus the drop is >20%.

### Attack B — the quality score misses "world-model utility"

Our score rewards long descriptions and long duration. It does not
reward *procedural density* — the presence of the action verbs a world
model actually needs to ground. A 15-minute philosophical monologue
about pasta beats a 6-minute "chop garlic, sauté, deglaze" clip.

**Hypothesis H2.** Adding an `action_density` heuristic (verb
occurrences in title + description + recipe_steps against a
domain-specific vocabulary) reorders the top-K per source in a way
that reduces the number of "trailer / montage / aftermovie" style
records surfaced.

### Attack C — the pipeline is cooking-only

The mission says "difficult video" domains, plural: surgery, lab work,
sports, manufacturing. Today every seed term is `["cooking", "recipe"]`.
Switching domain requires editing five files.

**Hypothesis H3.** A `domains` registry decoupled from source adapters
lets a single CLI flag (`--domain surgery`) re-run the harness across
all sources with domain-appropriate seed terms and verb vocabularies.
Nothing in the sources should need to change.

### Attack D — provenance is silently lying

`Provenance.extractor_git` defaults to `"dev"`. Under CI it stays
`"dev"`. In production it would still be `"dev"`. We cannot re-run any
report against a specific extractor commit, so the "reproducible
offline tests" pillar is only half-true.

**Hypothesis H4.** Stamping the real short SHA at import time (with a
`"dev"` fallback and no crash if git is missing) makes every record
in every future report reproducible against a specific commit.

### Attack E — the license classifiers have no adversarial fixtures

We have exactly one fixture per source and it contains only *happy
path* licenses. If tomorrow Wikimedia's `LicenseShortName` for a video
is `"CC-BY-NC 4.0"` the classifier's regex has to hit
`RESTRICTED` — but no test asserts this. Silent misclassification of
one NC license as `CC-BY` would poison a whole training corpus.

**Hypothesis H5.** Adding CC-BY-NC and CC-BY-ND adversarial fixtures
to every source, and asserting they classify as `RESTRICTED` (and
therefore `media_url is None`), catches all four current adapters if
they ever regress.

### Attack F — mypy is `|| true`, so type errors accumulate

CI runs `mypy src || true`. There are currently 7 pre-existing type
errors that are being ignored. This is bad hygiene: today's ignored
`Any | None` is tomorrow's runtime crash on a corner-case fixture.

**Hypothesis H6.** Removing `|| true` after cleaning up the
`AnyHttpUrl` and `list[tuple[str, str]]` mypy findings will lock the
codebase to a clean baseline that CI enforces going forward.

## How the next reviewer should attack this plan

1. Look at the `action_density` verb vocabulary. Is it too English?
   Test with a Japanese `料理` fixture — we will fail. Multilingual
   verb vocabs are a real follow-up.
2. Cross-source dedup uses `duration_s` bucketed to 2 s. Attack it with
   two records that share `duration_s=None`; today they will be
   treated as "same bucket" (both `None`), which is wrong. Confirm
   the module falls back to *not* deduping when either side lacks
   duration.
3. The domain registry hard-codes the verb vocabs in Python. This does
   not scale to 100 domains. If we ever exceed ~10 domains, move to a
   YAML/JSON file loaded lazily. Note this in the follow-up plan.
