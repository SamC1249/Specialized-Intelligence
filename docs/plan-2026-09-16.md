## Hypotheses under test today

- **H2 (Yield accounting).** The seed baseline double-counts: the same
  Wikimedia video can surface via Commons *and* via a Common Crawl
  page that embeds it. Without cross-source deduplication our reported
  `total_duration_s` is systematically inflated, so any yield claim
  based on it is anecdotal at best.
- **H3 (Topical drift).** Metadata quality (license, resolution,
  duration, text density) is *domain-agnostic*. A high-quality
  bird-watching video ranks the same as a high-quality cooking video.
  Adding a cheap, metadata-only *cooking-relevance* signal should
  meaningfully improve the fixture ranking on the target domain
  **without** requiring a video download.
- **H4 (Regression discipline).** Comparability requires deltas, not
  levels. A CI-runnable `compare-to-baseline` command that emits a
  machine-readable diff (and fails on regression beyond a tolerance)
  is a prerequisite to landing any future adapter or filter change.
- **H5 (Multilingual reach).** English-only search terms leave >70%
  of Wikimedia Commons and PeerTube cooking content unreachable.
  Even a small multilingual seed list (Spanish, French, Japanese,
  Hindi, Chinese, Arabic) plus a language-agnostic relevance signal
  is enough to prove the harness generalizes.

## Risks the next reviewer should attack

- Dedup keys are heuristic. False positives (dropping a legitimately
  distinct record) are worse than false negatives (dropping a dup).
  Tests should include an adversarial pair that looks close but is
  legitimately different.
- Multilingual keyword lists are seeded, not learned. Bias toward
  the seed languages is expected; document it and treat multilingual
  yield claims as lower bounds only.
- `compare-to-baseline` tolerance is a policy knob. Set it too tight
  and CI churns; too loose and the regression bar is meaningless.
  Default 0.02 abs / 5% rel is a starting point.
