# Adversarial-Agent Plan — 2026-09-16

Second real Adversarial-Agent turn. The bootstrap PR shipped four
license-aware adapters, a metadata-only quality scorer, a comparison
harness, offline fixtures, GitHub Actions matrix, and pre-commit. Today
we (a) attack the bootstrap's weakest spots, (b) fold in five external
papers as design pressure, and (c) tighten CI/pre-commit so future
regressions get caught.

## Bootstrap post-mortem — attacks that landed

The current codebase has multiple *silent* failure modes I want the
Coding-Agent to fix next:

1. **`--fixtures` is a placebo.** `cli.py:_cmd_compare` sets
   `by_source[slug] = []` for every source when `--fixtures` is set,
   so the "e2e" `ci-compare.json` uploaded by CI is structurally
   valid but semantically empty (all zeros). The `test_e2e_compare`
   test does the right thing directly in Python; the shipped CLI does
   not. **Fixed in this plan's PR.**
2. **License classifier for Wikimedia rejects many valid CC strings.**
   `_coerce_license("Attribution-ShareAlike 4.0") == UNKNOWN` — real
   Commons content is uploaded with this exact `LicenseShortName`.
   Same for `"GFDL 1.2"`, `"FAL"` (Free Art License), and any
   translation of "public domain". Documented under
   `tests/test_license_classification.py` (adversarial + `xfail` for
   known limitations).
3. **Provenance `extractor_git` is always `"dev"`.** AGENTS.md
   requires "the exact extractor commit hash" for every record.
   Fixable with a one-liner reading `GITHUB_SHA` or shelling out to
   `git rev-parse HEAD`. This plan's PR wires it up.
4. **No dedup.** Two records from two sources for the same NASA
   food-safety reel both count. `docs/artifacts/2026-09-16-video-dedup.md`
   spells out a three-tier design; today's PR ships the L1 skeleton
   (`quality/dedup.py` URL canonicalization) with tests and defers L2/L3.
5. **Quality scorer over-fits its own weights.** With
   `WEIGHTS["license_clean"] = 0.35` and the redistributable-set
   check, an `UNKNOWN` licence caps `mean_quality` at ~0.65 for any
   source — which is why `common_crawl` ranks below `peertube` even
   though its records carry real recipe steps. Fine for a baseline,
   *not* fine for a scientific ranking. We should split the
   `BenchmarkResult` view into "license-clean subset" vs "all
   records".
6. **CI mypy runs as `|| true`.** Effectively zero type coverage.
   Today's PR promotes mypy on `records.py` + `quality/metrics.py` to
   hard-fail so the tightest layer stays typed.

## Hypotheses under test (this and next turn)

- **H2 (yield).** Adding a *wikiHow-derived task inventory* (offline
  dump, ~4,958 titles restricted to `Category:Recipes`) as the query
  seed for Wikimedia Commons + Archive.org lifts license-clean hours
  discovered per crawl-day by ≥ 5×, with no drop in `mean_quality`
  on `reports/`.
- **H3 (dedup).** L1 (URL canonicalisation) + L2 (metadata bucket)
  dedup reduces cross-source `n_records` by ≥ 15% on Common
  Crawl-heavy queries. Measured as
  `(sum(per_source.n_records) - __total__.n_after_dedup) /
  sum(per_source.n_records)`.
- **H4 (procedural density).** Replacing `has_steps` (binary) with
  `n_steps_log = log(1 + n) / log(1 + 20)` shifts the ranking such
  that Common Crawl > Archive.org on `mean_quality` even when Common
  Crawl records have `UNKNOWN` license, because the *density* signal
  is what we actually want for world-model pretraining.
- **H5 (diversity).** For any single query, no author should hold
  more than 5% of returned records after dedup. If they do, the
  source is either under-crawled or being dominated by one uploader
  and the aggregate mean_quality is misleading.

## Risks the next reviewer should challenge

- Coverage floor set to 80% may be optimistic once we add heavier
  modules — reduce to 70% if flaky, do **not** disable.
- `git rev-parse` shelling out from Python is a foot-gun in
  containerised builds; the fallback chain must never raise.
- Adversarial license fixtures should not include actual live URLs
  we hit — keep them string-typed unit inputs.
- Adding `dedup` metrics changes `BenchmarkResult` shape, which
  invalidates historical `reports/baseline-2026-06-20.json`. The plan
  is: keep the old file as a historical checkpoint, and cut a new
  `reports/baseline-2026-09-16.json` in the *next* PR so the diff is
  reviewable.
