## TL;DR

The seed pipeline (`baseline-2026-06-20.json`) can only *see* what four
search endpoints choose to show us. If a source returns zero rows we
credit it as "empty" when in practice it is untested. This plan attacks
five gaps that show up when I re-read the seed with adversarial eyes:

1. **We have no live-crawl safety net.** Unit tests could quietly hit the
   network and no one would notice until CI turns brittle. → autouse
   socket-block fixture.
2. **We have no regression fence.** Nothing stops a PR from silently
   dropping mean quality from 0.62 to 0.20. → baseline-regression test
   tied to `reports/baseline-2026-06-20.json` with explicit tolerances.
3. **The `--fixtures` CLI mode is fake.** It reports all zeros, so the
   CI "E2E compare" step passes even if every adapter is broken. → wire
   `--fixtures` to actually load `tests/fixtures/**` through each
   adapter's `parse()`.
4. **Provenance is not enforced.** `AGENTS.md` demands it, but no test
   asserts every record has a non-empty `extractor` / non-`UNKNOWN`
   discipline. → invariant test that runs across all fixtures.
5. **We are one source-set deep.** The seed allowlist is fine but there
   are three under-utilised legal reservoirs we can extract *URL +
   metadata + license only* today: **Web Data Commons Schema.org Recipe
   corpus**, **Common Crawl CDXJ index**, and **Openverse** (see
   artifacts). We should design the adapter shape before writing code.

## Hypotheses under test

- **H1 (guardrail).** Adding a network-block fixture will *not* break
  the current suite. If it does, an adapter is doing I/O at import
  time — a real bug.
- **H2 (regression).** The current baseline is reproducible: rerunning
  the fixture-driven compare on the same fixtures yields identical
  per-source `mean_quality`, `n_records`, and `n_license_clean`.
- **H3 (yield ceiling).** Web Data Commons + Common Crawl CDX searches
  for `schema.org/Recipe` blocks with a nested `VideoObject` will
  produce ≥10x more candidate URLs per crawl-day than direct MediaWiki
  search — but only a small minority will pass license classification,
  because most recipe blogs are all-rights-reserved.
- **H4 (procedural signal).** Recipes annotated with ≥3 `HowToStep`
  entries have measurably higher downstream world-model utility than
  those without (Ego4D Goal-Step's ratio of ~23 steps per activity is
  the aspirational ceiling; see `docs/artifacts/2026-08-12-ego4d-goal-step.md`).

## Adversarial questions

1. **What if a source silently changes its schema?** We currently
   `.get(...)` everything and no test catches a rename. Should the
   `parse()` helpers strictly validate at least the license path?
2. **What if two sources return the same physical video?** e.g. a
   Blender Foundation short mirrored on both `video.blender.org`
   (PeerTube) and `archive.org`. We double-count `total_duration_s`
   today. Dedup is a v2 concern, but the `unique_authors` heuristic is
   a weak proxy.
3. **What if the license URL says CC-BY but the *page* is
   all-rights-reserved?** For Common Crawl the "page license" must win
   over any embedded `VideoObject`'s license claim. The current
   adapter defaults to `UNKNOWN`, which is safe. Document why.
4. **What if the fixture is the only thing we ever test?** The metric
   space is tiny. Add a *hostile fixture* per source: broken JSON, wrong
   license, absent duration, weird encoding. If `parse()` crashes,
   that's the bug.
5. **What if `quality_score`'s weights are arbitrary?** A weight
   ablation harness is v2 but this plan requires the weights be
   documented and tie-broken deterministically.

- [x] `tests/conftest.py`: autouse fixture that blocks all outbound
      TCP connects during unit tests (skips when `SPECINT_RUN_INTEGRATION=1`).
- [x] `tests/test_provenance_invariants.py`: for every adapter, run
      `parse()` over the checked-in fixture and assert
      `Provenance.extractor` is set and the module path matches the
      adapter module.

      `reports/baseline-2026-06-20.json`, rerun the same compare in
      pure code (no CLI), assert per-source
      `mean_quality`/`n_records`/`n_license_clean` match with a tight
      absolute tolerance.
- [x] `src/specint/cli.py`: `--fixtures` now walks `tests/fixtures/`
      and feeds each adapter's `parse()`. Emits a real report so the
      CI step is no longer a stub. Env var `SPECINT_FIXTURES_DIR` is
      honoured so downstream callers can point at a custom fixtures
      tree.
- [x] `.pre-commit-config.yaml`: add `mypy` (best-effort) and
      `codespell` (repo-wide) as pre-commit hooks; pin CI to the same
      versions.
- [x] `.github/workflows/ci.yml`: add
      `SPECINT_RUN_INTEGRATION=0` to all pytest invocations, and gate
      the "E2E compare" step on the exit code of a real compare.

## Out of scope for this iteration

- Any live network call in the default CLI path.
- Actual WARC iteration or WDC table download (bandwidth + storage
  outside a single VM).
- New adapters. All new sources are gated on a follow-up plan that
  cites the artifact above.
- Frame extraction, embedding, or perceptual-hash dedup. v2.

## Risks the next reviewer should challenge

- Baseline regression tolerances too tight → CI breaks on floating
  point drift. Chose `abs_tol=1e-9` for quality means but
  strict-equal on counts. If this flakes, loosen means to `1e-6`.
- Autouse socket-block may collide with a legitimate test that spins
  up a local httpx MockTransport. Mitigation: the fixture only blocks
  *outbound TCP connect*, not the `httpx.MockTransport` in-process
  path.
- WDC / CDXJ are legal but *very* large. Any adapter we build must
  short-circuit at index time based on structured filters.
- Perceptual-hash dedup is unavoidable at scale but comes with a
  compute cost that violates the "metadata-only" contract we've held
  so far. Keep it opt-in behind a flag when we finally ship it.
