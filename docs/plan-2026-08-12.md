# Adversarial-Agent Plan — 2026-08-12

> Written today because there was no fresh adversarial plan on disk and
> `plan.md` shows the 2026-06-20 seed items have all shipped. This plan
> attacks weaknesses in the baseline (see `reports/baseline-2026-06-20.json`)
> and sets the next benchmark bar.

## What the baseline actually shows

`reports/baseline-2026-06-20.json` (mean_quality per source, offline
fixtures, terms=`cooking recipe`):

| Source        | n | mean_quality | notes                                                |
| ------------- | - | ------------ | ---------------------------------------------------- |
| wikimedia     | 2 | 0.62         | best of the four; small fixture                      |
| peertube      | 2 | 0.57         | licence-ID filter works; language rarely surfaced    |
| common_crawl  | 1 | 0.53         | zero license-clean records — page license unknown    |
| archive_org   | 3 | 0.36         | duration parsing works, but resolution never set     |
| **__total__** | 8 | **0.50**     | new work must beat this on the same fixtures         |

Concrete weaknesses this plan attacks:

1. **Zero cross-source dedup.** A pasta video mirrored on Commons and on
   PeerTube's `framatube.org` will be counted twice, inflating yield and
   biasing mean_quality against low-duplication sources.
2. **No language signal.** `SourceQuery.language` is defined but never
   consumed by the harness; language-agnostic scoring silently favors
   English-title records.
3. **No procedural-density signal.** Cooking value for world-models comes
   from *step-structured* content. Today we only check `has_steps` as a
   boolean — a 12-step recipe scores the same as a 2-step one.
4. **Legal-source allowlist under-utilised.** AGENTS.md explicitly permits
   YouTube Data API listings restricted to `videoLicense=creativeCommon`
   (metadata only, no media download). We ship zero YouTube adapter.
5. **`search()` is untested.** Every unit test hits `parse()` on a fixture;
   nothing exercises the URL construction, param encoding, or
   error-handling paths in `search()`. A silent regression in query
   assembly would not fail CI.

## Hypotheses under test

- **H2.** A YouTube Data API adapter, constrained to
  `videoLicense=creativeCommon`, can meaningfully expand the license-clean
  frontier for cooking video *without* violating any hard constraint
  (URL + metadata only, no media download, no scraping).
- **H3.** A metadata-only *procedural-density* score (number of
  imperative-verb starts across title + description + recipe_steps)
  correlates with usefulness for procedural world-model training more
  strongly than the current binary `has_steps` flag.
- **H4.** A metadata-only *language-detection* heuristic (unicode-range +
  stopword lookup, zero dependencies) can label ≥ 90% of English cooking
  records correctly on our fixtures, enabling `SourceQuery.language` to
  actually filter results.
- **H5.** Cross-source deduplication via a
  `(normalized_title, duration_bucket, author_family)` fingerprint reveals
  non-trivial overlap between PeerTube mirrors and Internet Archive
  uploads. Reporting `overlap_ratio` per source pair is a durable metric
  the pipeline should track.

## Concrete deliverables for `Coding-Agent`

- [ ] `src/specint/sources/youtube.py` — `YouTubeCCSource`, strictly
      `videoLicense=creativeCommon`, `search()` requires
      `YOUTUBE_API_KEY` env (else returns `[]`), `parse()` is pure and
      unit-tested against a checked-in fixture. Media URLs are **never**
      populated (metadata + landing-page URL only).
- [ ] `src/specint/quality/language.py` — pure `detect_language(text) ->
      str | None` using unicode ranges + tiny stopword lookup.
- [ ] `src/specint/quality/metrics.py` — add `language_match` and
      `procedural_density` components; rebalance `WEIGHTS`; document the
      rationale.
- [ ] `src/specint/dedupe.py` — `fingerprint(record)`, `dedupe(records)`,
      and `overlap(by_source)` returning a JSON-serialisable overlap
      matrix per source-pair.
- [ ] `src/specint/compare/harness.py` — extend `run_comparison` to
      accept an optional `dedupe=True` and to include an `overlap` block
      in the report payload.
- [ ] `src/specint/cli.py` — new `python -m specint dedupe --fixtures`
      subcommand; `compare` gains `--dedupe`.
- [ ] Tests:
  - unit test for `youtube.parse`,
  - unit tests for `detect_language`, `procedural_density`,
  - unit + property-style test for `dedupe.fingerprint` stability,
  - **respx-mocked** integration tests for every adapter's `search()` so
    URL/params regressions are caught offline,
  - update `test_e2e_compare` to enforce
    `mean_quality(__total__) >= baseline − 0.02` guard so we can't
    silently regress.
- [ ] `reports/compare-2026-08-12.json` — committed, produced by
      `python -m specint compare --fixtures --dedupe`, and referenced
      from `plan.md`.
- [ ] CI: extend `.github/workflows/ci.yml` with a `specint dedupe
      --fixtures` step (fails if overlap block is missing).

## Out of scope today

- Actual YouTube API calls in CI (would need a secret; live smoke is
  gated behind `SPECINT_RUN_INTEGRATION=1` locally).
- Frame extraction, transcript scraping, or any download step.
- Non-English seed terms (H4 unlocks language filtering; multilingual
  seed-term expansion is the next plan's job).

## Risks the next reviewer should challenge

- Language detection with zero deps will misclassify short titles;
  fixtures must not over-fit. Cap fixtures at real-looking data.
- Dedupe fingerprints that collapse near-duplicates too aggressively
  will erase legitimate variety (e.g. two different pasta recipes).
  Report both `n_records` and `n_after_dedupe` so the trade-off is
  visible.
- YouTube's ToS permit metadata display, not bulk re-hosting. We must
  never populate `media_url` for YouTube records, even when the license
  says CC-BY.
