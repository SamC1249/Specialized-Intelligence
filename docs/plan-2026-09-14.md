## Hypothesis under test

> **H2.** The 2026-06-20 baseline is *artificially* separated from
> production reality by three unforced errors: (a) English-only seed
> terms, (b) per-adapter ad-hoc license regex that will drift as we add
> sources, and (c) Common Crawl records that inherit whatever license
> the JSON-LD block claims rather than the license the *page* claims.
> If we fix (a)–(c) as **cross-cutting library code** (not per-adapter
> patches) and re-score the same fixtures plus a new
> non-English/non-JSON-LD-lied fixture, mean quality of license-clean
> records should rise and total license-clean count should not fall.

## Why this is a frontier problem

Cooking is one instance of *procedural long-horizon video*. The generic
frontier problem is:

> Given the entire public web, systematically enumerate,
> license-classify, and *rank* every piece of long-horizon procedural
> video without paying, without ToS violations, and without discarding
> anything just because it is not in English.

Every piece of infrastructure we build for cooking must trivially retarget
to surgery, manufacturing assembly, sports drills, lab protocol demos.
That means: (i) seed terms are a **domain profile**, not a hard-coded
constant, (ii) license logic is **not** per-source, and (iii) the quality
score is a linear combination of pluggable, unit-tested components.

## Adversarial questions to attack today

1. **License drift.** Each adapter currently has its own regex-y
   `_license_from_*` helper. If a fifth adapter is added tomorrow, will
   it accidentally accept `CC-BY-NC` as clean because someone typed
   `"cc-by"` in a substring check? Centralize.
2. **Common Crawl lies.** A recipe page can legally be `RESTRICTED`
   while its embedded YouTube `VideoObject` claims a `contentUrl` on a
   CDN. We must always classify by *page* license (e.g. `<link
   rel="license">`) — not by whatever the JSON-LD says.
3. **English monoculture.** Our seed terms are two English words. That
   is a distribution bug, not a research limitation.
4. **Domain-agnosticism.** Can our current stack ingest a *surgery*
   query today, offline, with zero code changes? If not, the
   generalization claim is aspirational.
5. **Scoring interpretability.** `quality_score` mixes five components
   into one float. If tomorrow we want to A/B a new scorer, do we have
   the harness plumbing to run both scorers on the same corpus and diff
   the ranks?

## Concrete deliverables for `Coding-Agent`

- [ ] `src/specint/licenses.py` — single classifier: URL, SPDX
      short-name, and MediaWiki `extmetadata` short-name → `License`.
      Every adapter must import from here.
- [ ] `src/specint/language.py` — script-based, dependency-free
      language detection (Latin / Cyrillic / CJK / Arabic / etc.) plus
      common function-word heuristics for a small set of European
      languages. Adds a `_score_language` component to the quality
      scorer (0 if we cannot tell, 1 if we can confidently tag).
- [ ] `src/specint/domains.py` — `DOMAINS` registry mapping domain slug
      (`cooking`, `surgery`, `manufacturing`) to per-language seed
      terms. CLI grows `--domain <slug>` and `--language <bcp47>`.
- [ ] Common Crawl: `parse_recipe_html` extracts page-level
      `<link rel="license">` and `<meta name="copyright">`, and this
      page license overrides any per-video JSON-LD claim.
- [ ] CLI `--fixtures` mode: currently a stub — it must actually load
      every fixture in `tests/fixtures/*` and run the harness on real
      records. Otherwise the harness is unreproducible outside of
      pytest.
- [ ] Comparison harness: emit **two** rows per source when
      `--scorer-variant baseline,plus-language` is passed, so scorer
      experiments are directly diffable in one report.
- [ ] Tests: license classifier round-trip, language detector on real
      strings, domain registry contract, updated Common Crawl fixture
      with a CC-BY-SA `rel=license` badge, new CLI test that loads
      fixtures.
- [ ] Fresh `reports/compare-2026-09-14.json` — must not regress
      mean-quality of the license-clean subset relative to
      `reports/baseline-2026-06-20.json`.

## Out of scope today

- Live network fetches (still gated by `SPECINT_RUN_INTEGRATION=1`).
- ML-based language detection (`fasttext-lid`, `langdetect`) — we do
  *not* want a heavy dep before we have the harness to A/B it.
- Adding a new upstream source; the payoff-to-risk ratio of hardening
  the existing four beats adding a fifth that will inherit the same
  three unforced errors.

## Risks the next reviewer should challenge

- Script-based language detection will call `"chocolat"` French and
  `"pesto"` Italian based on stopword luck. Document accepted failure
  modes; do **not** put language on the redistributable/not path.
- Domain profiles are only as good as their seed terms; commit them so
  the diff is legible and criticisable.
- Any component we add to `WEIGHTS` re-normalizes all previous weights.
  Bake this into a regression test (the score of a known record must
  not drift by > 5% unless weights are intentionally rebalanced).
