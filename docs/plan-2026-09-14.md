# Adversarial-Agent Plan — 2026-09-14

> Prior state of the world: `2026-06-20` bootstrap shipped 4 offline
> adapters (Wikimedia Commons, Internet Archive, PeerTube single-instance,
> Common Crawl HTML JSON-LD), a metadata-only quality scorer, a compare
> harness, and CI. Baseline (`reports/baseline-2026-06-20.json`) —
> `wikimedia 0.62 > peertube 0.57 > common_crawl 0.53 > archive_org 0.36`.
> No entry has landed since; the plan below is what an adversary would
> attack first.

## Hypotheses under test

> **H2.** The `2026-06-20` baseline is **over-fit to fixtures**: it
> rewards license and text density but has no signal that would
> distinguish a 240p slideshow from a 1080p multi-object procedural
> capture. A single new quality component (caption/subtitle presence +
> thumbnail geometry from a HEAD probe) should meaningfully re-rank the
> corpus without downloading any media bytes.
>
> **H3.** Our current legal-source allowlist under-samples Europe and
> heritage collections by an order of magnitude. Adding **Europeana**
> (Tier-4 open-rights video) and **NASA images-api** (public-domain
> government footage, with WebVTT captions) will each contribute
> `>= 2×` the license-clean hours per crawl-day of Internet Archive,
> at zero legal risk.
>
> **H4.** For PeerTube we are only querying a single hard-coded
> instance. Swapping that for **Sepia Search** (`sepiasearch.org`, a
> public API that indexes the entire PeerTube federation) will Pareto-
> dominate the single-instance adapter on yield and unique-author
> diversity without changing any legal posture.
>
> **H5.** Our `common_crawl` adapter is parsing HTML page-by-page in a
> loop that only ever sees fixtures. The **Web Data Commons** project
> already publishes pre-extracted `schema.org/Recipe` and
> `schema.org/VideoObject` N-Quad subsets of the October-2024 crawl
> (~2.75B recipe quads; ~10⁶–10⁷ VideoObject domains). Reading those
> corpora is `>= 100×` cheaper per hour of legally-clean recipe video
> discovered than the current strategy, and does not violate any ToS
> because WDC is CC-BY.
>
> **H6.** Our records store `provenance.extractor_git = "dev"` by
> default. AGENTS.md hard-constraint #2 (provenance is *mandatory*,
> including "exact extractor commit hash") is therefore silently
> violated in every non-CI run. There is no test enforcing it. If
> anyone ever ships a training corpus off a local checkout, we lose
> the audit trail.

## Attacks / adversarial questions for today

1. **Fixture over-fit.** Re-run `compare` under permuted fixtures
   (drop the highest-quality record from each source) and re-check the
   ranking. If the ordering flips, our scorer is dominated by outliers,
   not by signal.
2. **Duplicate leakage.** The same video (e.g. NASA cooking-in-space)
   plausibly appears on Wikimedia *and* Internet Archive. We currently
   count it twice. Sketch a title+duration+author LSH sketch that runs
   in `O(n log n)` before aggregation, and quantify the collision rate
   on fixtures.
3. **License leakage.** Wikimedia Commons carries a small tail of
   *uploaded-in-error, non-CC* files (`Template:PD-USGov` misuse, deleted
   uploads with stale metadata). Add a negative fixture and assert we
   default to `License.UNKNOWN` instead of `License.CC_BY_SA`.
4. **Domain generalization.** Everything in `quality/metrics.py` is
   secretly cooking-specific ("`recipe_steps`", 5-minute duration
   target). A surgery or lab-work plan would silently score 0 on
   `has_steps`. Refactor: promote a `DomainProfile` (weights + query
   packs + expected duration curve) so cooking → surgery → sports →
   manufacturing reuse the pipeline unchanged.
5. **Silent network usage.** Nothing in CI proves `parse()` never
   opens a socket. If a future adapter accidentally puts a
   `httpx.get(...)` inside `parse`, our "offline" contract dies. Add a
   sentinel test that monkey-patches `socket.socket` and re-runs the
   e2e compare, expecting zero connections.
6. **Baseline non-regression.** Nothing prevents a future PR from
   dropping `mean_quality` by 20% and still shipping a green CI. Add
   a JSON diff test against `reports/baseline-2026-06-20.json` with
   an explicit tolerance envelope (`±0.03` per source, ±0 for
   `n_license_clean`).

## Concrete deliverables (`Coding-Agent`)

Priority-ordered. Each item must ship with a benchmark row and a test.

### P0 — Guardrails (prevents regressions before we add features)

- [ ] `tests/test_offline_contract.py` — socket-sentinel test that runs
      the full e2e compare with `socket.socket` patched to raise, and
      asserts all four adapters return records purely from fixtures.
- [ ] `tests/test_baseline_nonregression.py` — loads
      `reports/baseline-2026-06-20.json`, re-runs the fixture compare,
      and asserts `mean_quality`, `n_records`, and `n_license_clean`
      per source are within a documented envelope of baseline.
- [ ] `tests/test_provenance_integrity.py` — parametric across every
      registered source; asserts every emitted `VideoRecord` has
      `provenance.extractor` non-empty, `provenance.fetched_at`
      timezone-aware UTC, `provenance.query` non-empty, and
      `provenance.extractor_git` != `""`. Introduces the *first* test
      that will fail today (see H6) — that failure is the point.
- [ ] `src/specint/_git.py` — a `resolve_commit()` helper that reads
      `git rev-parse --short HEAD` at import time (fall back to the
      `SPECINT_GIT_SHA` env var if set, then `"dev"`). Wire it into
      every adapter's `Provenance(...)`.
- [ ] `.pre-commit-config.yaml` — add a local `file-size-guard` hook
      that fails if any tracked `*.py` file exceeds 800 lines (repo
      style rule — currently only enforced by convention).

### P1 — Cheap, high-yield new sources

- [ ] `src/specint/sources/europeana.py` — adapter for
      `https://api.europeana.eu/record/v2/search.json` with
      `qf=TYPE:VIDEO&qf=REUSABILITY:open` (returns only CC0 / CC-BY /
      CC-BY-SA / PDM). Requires only an unauthenticated `wskey=api2demo`
      or free API key. Fixture-tested from a canned JSON response.
- [ ] `src/specint/sources/nasa_images.py` — adapter for
      `https://images-api.nasa.gov/search?media_type=video`, all
      records are `License.PUBLIC_DOMAIN` by policy. Bonus: pull
      caption VTT URL via `/captions/{nasa_id}` and store as
      `keywords` seed.
- [ ] `src/specint/sources/loc.py` — adapter for
      `https://www.loc.gov/search/?fa=original-format:film/video&fo=json`.
      Only accept records whose `rights` string matches
      `no known copyright|public domain|U.S. government`, else default
      to `License.UNKNOWN`.

### P1 — Upgrade existing sources

- [ ] `src/specint/sources/peertube.py` — accept an
      `instance_url` init arg but default to
      `https://sepiasearch.org` (federation-wide search) and update
      fixtures / adapter tests accordingly. Store the *origin*
      instance URL in `Provenance.query`.
- [ ] `src/specint/sources/common_crawl.py` — add a second entrypoint
      `from_wdc_nquads(path)` that consumes a Web Data Commons
      `schema_Recipe.nq.gz` shard. Ship one small (`<50KB`) checked-in
      sample under `tests/fixtures/common_crawl/wdc_recipe_sample.nq`.

### P2 — Quality signals that don't require downloading video

- [ ] `src/specint/quality/metrics.py` — add three components (each in
      `[0, 1]`, each documented):
  - `has_captions` — 1 iff record advertises captions/subtitles URL
    (Wikimedia `subtitles`, NASA `/captions/{id}`, WebVTT links in
    PeerTube).
  - `thumbnail_geometry` — parse thumbnail URL for `_1280.jpg`-style
    hints; else 0. Placeholder for a future HEAD-probe.
  - `procedural_verb_density` — count `["mix","stir","chop","boil",
    "add","heat","bake","fry","whisk","fold"]` (imperative verbs) in
    title+description+recipe_steps, normalize by token count.
    Trivially swappable for domain-specific verb lists.
- [ ] `src/specint/quality/domains.py` — introduce `DomainProfile`
      (weights + expected-duration curve + verb list) and wire it
      through `score_record(record, profile)`. Cooking is the default;
      ship a stub `surgery` and `manufacturing` profile too.

### P2 — Comparison harness upgrades

- [ ] Emit `median_records_per_author` and a rough `dedup_rate` (based
      on the LSH sketch from attack #2) into every `BenchmarkResult`.
- [ ] `python -m specint compare --profile surgery` should run against
      the same fixtures but re-weight quality with the surgery
      `DomainProfile`, proving the pipeline generalizes.

## Out of scope today

- Downloading any video bytes (still URL+metadata only).
- Any source requiring paid API keys.
- Vimeo CC search: Openverse routes users to `vimeo.com/search?license=by`
  but Vimeo's API forbids programmatic download and rate-limits search
  aggressively; keep it as a "URL pointer only" option in a future plan.
- YouTube Data API CC-filter: allowlisted by AGENTS.md but demands an
  API key; defer until we have a secret-management story in CI.

## Risks / traps the next reviewer should challenge

- **Europeana `REUSABILITY:open` still exposes CC-BY-SA-only clips**;
  we must propagate the exact license tag, not collapse to `CC_BY`.
- **WDC N-Quads are large.** Do not check in > 50KB fixtures; use
  `git lfs`-free samples generated by a `scripts/synth_wdc_sample.py`
  helper if the real thing is too big.
- **Sepia Search rate-limits.** Add a `Retry-After`-aware backoff
  before we point CI at it (CI must stay offline; this is only for the
  live integration suite).
- **`git rev-parse` at import time** is a footgun in `sdist`
  installs. `_git.resolve_commit()` must swallow every exception and
  fall back to the env var / `"dev"`.
- **Baseline non-regression can become an anti-pattern** if it makes
  every improvement require re-baselining. Mitigate by keeping a
  *floor* baseline (never re-baseline downward) and an explicit
  `--record-baseline` CLI flag that requires human review of the diff.
