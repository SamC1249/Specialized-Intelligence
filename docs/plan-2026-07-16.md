## Consolidated adversarial claims (both 07-14 drafts agree)

- **H5 (CLI --fixtures returns zeros).** `python -m specint compare
  --fixtures` currently produces an empty aggregate because the CLI
  never actually loads `tests/fixtures/`. The e2e test bypasses the
  CLI, so CI hides the bug.
- **H6 (provenance not reproducible).** Every `Provenance` record
  ships with `extractor_git="dev"`. AGENTS.md rule 2 requires the
  exact extractor commit hash — currently we lie.
- **H2/H3 (scorer coarse + license regex fragile).** `license_clean`
  dominates the metadata-only score; regex-based license
  classification silently drops unseen CC-BY-NC / GFDL / NBSP-
  whitespace variants; there is no adversarial table.
- **H4 / dedup absent.** Same `VideoRecord.id` fed twice, or the same
  clip federated across two PeerTube instances / mirrored to Archive,
  is currently counted twice. `BenchmarkResult` has no `n_duplicates`.
- **Single-query benchmarks lie.** One `SourceQuery` is not a
  benchmark. We need a `SourceQuerySuite` with N queries per source.
- **Common Crawl stuck at UNKNOWN.** The parser never inspects
  `<link rel="license">`, `<meta name="license">`, JSON-LD `license`,
  or `og:license`. Many food-blog CMSes emit exactly those.
- **Reports aren't comparable across days.** No `python -m specint
  diff` — two JSON reports can't be diffed mechanically.
- **English-only bias.** All seed terms are English. Cooking is a
  multilingual domain and we haven't even set up multilingual
  fixtures to expose the bias.

## Metrics we're now tracking across daily runs

Same core as before (`n_records`, `n_license_clean`,
`total_duration_s`, `mean_quality`, `p50_quality`, `p90_quality`,
`unique_authors`) plus:

- `n_duplicates` — per-source ID collisions collapsed by the harness.
- `scorer` — which scorer version produced `mean_quality`.
- (Aggregated in `reports/matrix-*.json`) per-source mean-quality
  **variance** across the query suite — high variance = a source
  whose benchmarks we cannot trust from a single query.
