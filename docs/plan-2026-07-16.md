# Adversarial-Agent Plan — 2026-07-16

> Prior plans read: `docs/plan-2026-06-20.md` (bootstrap). Baseline in
> `reports/baseline-2026-06-20.json`. Since then the seed pipeline has
> shipped four adapters and a comparison harness but nothing has moved
> the baseline. Time to attack.

## Where we are

- Baseline mean quality per source on the seed fixtures:
  wikimedia 0.62 > peertube 0.57 > common_crawl 0.53 > archive_org 0.36.
- Quality scoring is metadata-only (license, duration, resolution, text
  density, has_steps). No dedup, no language detection, no cross-source
  join, no C2PA, no provenance verification.
- Tests are offline but nothing prevents a future PR from silently
  regressing the baseline, and nothing prevents an adapter from
  accidentally issuing live HTTP inside a unit test.

## Hypotheses under test today

> **H2 — Yield ceiling.** For the current allowlist, the number of
> *license-clean, procedural, English cooking* videos discoverable per
> crawl-day is bounded above by roughly 10⁴ from Wikimedia + IA + PeerTube
> combined. Common Crawl JSON-LD is the only route to move that number
> into the 10⁵+ range, but doing so requires page-level license
> verification, not video-level.

> **H3 — Dedup is the biggest lever.** Cross-source and within-source
> near-duplicates (mirrored Blender demos on multiple PeerTube instances,
> multiple Wikibooks-derived recipe pages, Archive.org reuploads) inflate
> yield by an estimated 1.3-2.0×. A cheap MinHash / SimHash pass on
> title+description+URL host will beat any resolution or duration filter
> at improving mean_quality-per-unique-hour.

> **H4 — Procedural density predicts downstream usefulness better than
> resolution.** For world-modeling, an 480p video with 12 explicit recipe
> steps is worth more than a 4K vlog with none. Our current WEIGHTS give
> them ~equal weight; that's wrong and testable.

> **H5 — Provenance we can *verify* > provenance we merely *record*.**
> Signed C2PA manifests are the only way to detect training-opt-out and
> the only way to defend a corpus against a future takedown wave. Even a
> stub (SHA-256 of raw payload + extractor SHA) closes the biggest hole.

## Adversarial questions to attack

1. **What would a hostile reviewer say about our license classification?**
   - Wikimedia adapter falls through to `UNKNOWN` on any unrecognised
     `LicenseShortName`; we treat `UNKNOWN` as non-clean, but we never
     count how often the fallthrough fires. Add a metric.
   - Archive.org licence detection is substring-based on the URL. A
     licence URL like `.../by-nc/` currently correctly returns
     `RESTRICTED`, but `.../by-nd/4.0/` also does — good — however a
     licence URL for a Creative Commons 0 file that only writes
     `creativecommons.org/publicdomain/mark/1.0/` would be classified as
     `PUBLIC_DOMAIN` even though `mark` is *not* CC0. Test it, tighten
     it.
2. **Can we detect duplicates cheaply?** Prototype a `dedup.py` using
   64-bit SimHash over token-shingled title+description (Charikar 2002,
   Manku 2007). Report `n_unique_records` and mean quality *per unique
   record* alongside the current metrics.
3. **Can we honour `cawg.training-mining` opt-outs today?** Parse
   `<meta name="c2pa">` sidecar links and JSON-LD
   `usageInfo`/`copyrightNotice` blocks on Common Crawl pages. Any record
   whose page carries a training-opt-out becomes `RESTRICTED`.
4. **Is our test discipline sufficient?** Currently *nothing* stops a
   test file from importing `httpx.Client()` or `urllib.request.urlopen`.
   Add an offline-guard test that scans `tests/` for such calls.
5. **Can we detect a silent baseline regression?** Add a regression test
   that runs the harness against the checked-in fixtures and asserts
   per-source `mean_quality` is within a tolerance of the recorded
   baseline. New sources should be added by *appending* rows, never by
   accidentally dragging existing scores down.

## Out of scope today

- Actual video download and perceptual hashing (frame-level pHash) —
  waits until dedup on metadata is landed and evaluated.
- Multilingual search terms — needs a language-detection pass first;
  filed as follow-up in H2.
- Distributed crawl infra — single process still fine until we hit the
  10⁴ ceiling.

## Risks the next reviewer should challenge

- SimHash on title+description alone will over-collapse different
  recipes with similar names ("garlic butter pasta" appears on hundreds
  of blogs). Mitigation: also shingle on host + duration bucket.
- Baseline regression test creates a *ratchet* — a legitimately better
  quality function will need to update the baseline in the same PR.
  Document the update path in `AGENTS.md` so it doesn't become a
  merge-blocker for good work.
- C2PA-style payload hashing is only meaningful if we also archive the
  raw payload. We are metadata-only for now — record the hash but do
  not gate ingestion on it until we have a raw-payload store.
- Openverse aggregates upstream providers whose per-item licence can
  change; store `license_url` verbatim and re-validate on every crawl.

## Metrics we will report in tomorrow's `reports/compare-2026-07-17.json`

Per source, plus `__total__`:
- `n_records`, `n_unique_records`, `n_license_clean`
- `mean_quality`, `mean_quality_unique`, `p50_quality`, `p90_quality`
- `total_duration_s`, `unique_authors`
- `license_audit.n_unknown_fallthrough`

Success criterion: **`mean_quality_unique` for `__total__` beats the
2026-06-20 baseline `mean_quality` (0.499) by ≥ +0.02** *without*
reducing `n_records` on any single source. If we can't clear that bar,
we document the negative result and iterate.
