## What the 2026-06-20 baseline told us

`reports/baseline-2026-06-20.json` (fixture-only) ranks sources by
mean quality:

    wikimedia    0.62
    peertube     0.57
    common_crawl 0.53
    archive_org  0.36

Three uncomfortable facts jump out:

1. **`common_crawl` is scored generously even though `n_license_clean=0`**
   for that source in the baseline. The v1 scorer gives credit for
   duration / resolution / text density and only *lightly* penalises an
   unknown license (0 out of a 0.35 weight). That means a page we cannot
   legally redistribute can outscore a Wikimedia CC-BY-SA clip. Fixing
   this is a legal-risk fix, not just a quality fix.
2. **No dedup exists.** A Wikimedia video embedded in a Common Crawl
   recipe page currently double-counts, inflating `n_records`,
   `total_duration_s`, and the aggregate `__total__` mean quality. Any
   claim about "hours of unique CC video" is presently unfalsifiable.
3. **Everything is cooking-specific.** The mission (AGENTS.md) requires
   the system to generalise to surgery / lab / sports / manufacturing.
   Today the CLI hard-codes `DEFAULT_TERMS = ["cooking", "recipe"]` and
   the scorer's textual signals are cooking-agnostic only by accident.

## Hypotheses under test today

- **H1 (domain-generality).** *A single-config change swaps the target
  domain from cooking → laboratory (or surgery, sports, …) and the
  pipeline yields non-zero records with a plausible per-source ranking,
  proving the code is not implicitly cooking-shaped.* Falsifiable by:
  running the harness against a `laboratory` fixture set and asserting
  the same invariants hold.
- **H2 (dedup is meaningful, not cosmetic).** *At least one pair of
  fixture records across sources collapses under a metadata-only dedup
  policy (url canonicalisation ∨ (title-shingle Jaccard ≥ 0.8 ∧
  duration-bucket match)). After dedup, `__total__.n_records` decreases
  while per-source `n_records` do not, showing the dedup happens at
  aggregation time only.*
- **H3 (Common Crawl license enrichment).** *Adding a page-level
  Creative Commons license extractor (`<link rel="license">`,
  `<meta name="dcterms.rights">`, `<meta property="og:license">`,
  and standalone CC URL detection in body links) turns at least one
  fixture record from `License.UNKNOWN` into a redistributable
  license. Records the extractor marks `CC0/CC-BY/CC-BY-SA/PD` must
  cite a license URL in `license_url`; nothing is upgraded silently.*
- **H4 (procedural verbs are a domain-portable quality signal).**
  *Counting procedural verbs in `title + description + recipe_steps`
  ranks known-good procedural fixtures above talking-head fixtures.
  The verb list is per-domain (cooking verbs ≠ surgery verbs) and lives
  in `specint.domains`, not hard-coded in the scorer.*
- **H5 (scorer v2 dominates v1 on procedural-density Kendall τ).**
  *On the fixture corpus, quality scorer v2 (procedural verbs + license
  tier + neutral-unknown) has Kendall τ ≥ v1 against the "good = license
  clean ∧ duration ∈ [60s, 30min] ∧ steps ≥ 3" ground truth. Documented
  as a `reports/ablation-2026-07-12.json` row so we can never regress
  silently.*

## Risks the next reviewer should attack

- **Dedup false-positives.** Title-shingle Jaccard ≥ 0.8 will collapse
  short, generic titles like "Pasta" and "Pasta with garlic". Mitigation:
  require duration-bucket match too, and never merge across
  `license` boundaries (a CC0 record cannot inherit a RESTRICTED
  duplicate's metadata, and vice versa).
- **License-tier scoring** is a value judgement. We set CC-BY above
  CC-BY-SA because share-alike is a real training-corpus poison
  vector. If a reviewer disagrees, they need a report row, not a
  code comment.
- **Domain generality is claimed, not proven.** We ship a `laboratory`
  fixture, but three domains are not "internet-scale generality". The
  test is *falsifiability*, not *coverage*: if `laboratory` breaks
  because of a hidden cooking assumption, we catch it today.
