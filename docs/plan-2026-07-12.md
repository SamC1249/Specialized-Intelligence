# Adversarial-Agent Plan — 2026-07-12

> Author: `Adversarial-Agent`. Prior plan: `docs/plan-2026-06-20.md`
> ("H1: Wikimedia + Internet Archive + Common Crawl Pareto-dominate on
> yield × license × resolution × procedural density"). The seed
> `Coding-Agent` shipped H1's minimum-viable pipeline and the first
> baseline (`reports/baseline-2026-06-20.json`). This plan attacks the
> weakest links in that baseline.

## 1. Where the current pipeline is *provably* wrong

Concrete failure modes I can demonstrate against today's code:

1. **License classification is regex-fragile and asymmetric across
   sources.** Each adapter re-implements license normalisation
   (`_coerce_license`, `_license_from_url`, `_peertube_license`). None
   of them share a golden test set. A Wikimedia entry that says
   `"cc by 4.0"` (lowercased, spaces) is mapped to `CC_BY`, but the same
   record with `"Attribution 4.0 International"` (Commons' other common
   label) falls to `UNKNOWN`. That silently deletes yield.
2. **`archive.org` mapping constructs `media_url` blindly** as
   `download/{id}/{id}.mp4`. Internet Archive items regularly ship
   `.ogv`, `.mkv`, or no derivative at all — those URLs 404. This
   inflates "license-clean redistributable" without evidence.
3. **`peertube` uses a static instance allowlist** with no health check.
   If one instance goes offline, we quietly under-report yield with no
   log line, and CI never notices because CI is fixture-only.
4. **`common_crawl` never actually reads WARCs.** The `search()` method
   returns `[]`. Our baseline includes it, but the number is a
   fixture — we cannot claim it as evidence for H1.
5. **No dedup.** The same recipe (e.g. Blender Foundation's *Big Buck
   Bunny* cooking short mirror) can appear in Wikimedia *and* Internet
   Archive *and* a PeerTube mirror. Today's `__total__` row adds them
   naively, so cross-source union yield is systematically inflated.
6. **Quality score is uncalibrated.** The weights in
   `quality/metrics.py` were chosen by intuition, never against a held-out
   gold set. We have no way to know if `mean_quality=0.62` on Wikimedia
   is a good number or noise.
7. **CI enforces lint, format, and tests — but not the
   "comparison-first" rule from `AGENTS.md`.** A future PR can add a new
   source and skip the `reports/` update; nothing fails.
8. **Zero adversarial input tests.** No fixture exercises malformed
   JSON, HTML with `<script>` bombs, absurd `duration_s`, negative
   `height`, Unicode-abuse titles, sneaky license strings like
   `"CC-BY-NC hidden as CC-BY"`.

## 2. Hypotheses to test today

- **H2 (Dedup).** Metadata-only near-dup detection using
  `(normalized_title_shingles, duration_bucket, author_slug)` collapses
  ≥5% of records on our current baseline fixtures without dropping any
  gold "not-duplicate" pair. If true, we should *require* the harness to
  report a `n_unique_after_dedup` alongside `n_records`, and the
  `__total__` row should use the deduped set.
- **H3 (Shared license normalisation Pareto-improves recall).** A
  single `license.classify(strings: list[str]) -> License` fed all
  candidate strings from every adapter (`extmetadata.LicenseShortName`,
  `licenseurl`, `licence.name`, and page-level `<link rel="license">`)
  achieves ≥ current per-adapter classifier on today's fixtures and
  strictly better on synthesized adversarial fixtures.
- **H4 (Comparison-first is enforceable in CI).** A GitHub Actions job
  can diff `reports/*.json` against `main` on every PR that touches
  `src/specint/sources/` or `src/specint/quality/`, and fail if no new
  benchmark row was added or if `mean_quality` regressed by more than
  `epsilon = 0.02` on any existing source without an accompanying
  `docs/plan-*.md` entry justifying it.
- **H5 (YouTube CC listings are legally in-scope for metadata).**
  `AGENTS.md` explicitly allows YouTube Data API v3 with
  `videoLicense=creativeCommon` for **URL + metadata only** (not media
  download). Empirically, this yields the largest single stream of
  license-clean cooking video *pointers* on the open web. We should ship
  an offline-fixtured `YouTubeCCListingSource` today, gated on
  `SPECINT_YT_API_KEY` for live calls, and add it to `REGISTRY` so it
  shows up in `compare` outputs.

## 3. Concrete deliverables for the next `Coding-Agent` run

Ordered by leverage-per-line-of-code, so partial completion still
compounds.

- [ ] **Shared license classifier** — new
      `src/specint/quality/license_utils.py` with a pure
      `classify(*candidates: str | None) -> License` and a
      `LICENSE_PATTERNS` table. Refactor all four adapters to call it.
      **Add adversarial fixtures**: strings like `"CC BY 4.0"`, `"cc-by-sa"`,
      `"Attribution-NonCommercial-ShareAlike 4.0"`, `"public domain"`,
      `"copyright holder"`, `""`, `None`, and Unicode ZWJ-attack variants.
- [ ] **Metadata-only dedup** — new
      `src/specint/quality/dedup.py` with `dedup_key(record) -> str`
      and `dedup_records(records) -> tuple[list[VideoRecord], list[Cluster]]`.
      Wire it into `compare.harness.run_comparison` so the `__total__`
      row uses the deduped union, and record cluster count in
      `BenchmarkResult.notes`.
- [ ] **`BenchmarkResult` schema extension** — add
      `n_unique_after_dedup: int` and a computed `dedup_rate: float`.
      Update `db_structured.md` in the *same* PR so schemas stay canonical.
- [ ] **CI benchmark-guard workflow** — new
      `.github/workflows/benchmark-guard.yml` that runs on PRs touching
      `src/specint/sources/**` or `src/specint/quality/**` and requires
      either (a) a new file under `reports/` or (b) the PR body to include
      the string `NO-BENCHMARK-JUSTIFY:` followed by ≥ 20 chars of prose.
- [ ] **Pre-commit hardening** — add `mypy` (best-effort, non-blocking
      already, but move to a dedicated hook), a
      `check-json` hook against `reports/*.json`, and a local
      `precommit-compare` hook that runs `python -m specint compare
      --fixtures --output reports/.precommit.json` and asserts the file
      parses (guards against harness regressions).
- [ ] **YouTube CC listings adapter (metadata-only, offline-fixtured).**
      New `src/specint/sources/youtube_cc.py`. `search()` must refuse to
      run without `SPECINT_YT_API_KEY`; `parse()` handles a
      `search.list` + `videos.list` merged JSON fixture and emits records
      with `media_url=None` (we never download).
- [ ] **Adversarial parser fixtures.** For every existing adapter, add
      one fixture representing an actively hostile upstream: empty
      response, malformed JSON, extra top-level keys, oversize integers,
      non-UTF8 bytes, and a `LicenseShortName` claiming CC-BY when the
      full URL is CC-BY-NC. Each must round-trip through `parse` without
      raising and either drop the record or mark it `UNKNOWN`.
- [ ] **`docs/artifacts/` seed.** Land 2–3 research notes with citation,
      one-paragraph summary, and an "how this changes our pipeline"
      bullet list. Today's seeds: V-JEPA 2 cluster-based curation on
      YT-1B, YFCC100M CC-video sub-corpus, and perceptual-hash near-dup
      detection at scale. Rationale: these three papers directly inform
      H2 (dedup), H5 (upstream selection), and future
      `quality/curation.py` work.

## 4. Explicit non-goals for today

- No live network calls in tests. All adversarial fixtures live under
  `tests/fixtures/adversarial/`.
- No perceptual video hashing yet. That requires downloading frames,
  which the harness explicitly avoids at ranking time. Land it *after*
  we have the metadata-only baseline it must beat.
- No new upstream source beyond YouTube-CC (metadata). Broader
  federated search across every PeerTube instance requires a discovery
  service and is out of scope.
- No changes to `License` enum values. Extending the enum is a schema
  change that needs its own plan entry.

## 5. Risks the Reviewer-Agent (future) should attack

- **License classifier over-permissiveness.** A shared classifier is
  only better if it is *conservative* on ambiguous inputs; we must fail
  closed to `UNKNOWN`, never open to `CC_BY`. Reviewer must confirm the
  adversarial test set includes at least one string that *should* stay
  `UNKNOWN`.
- **Dedup key collisions.** `(title_shingles, duration_bucket, author)`
  can collide on genuinely different content ("Chocolate Cake" of
  ~5 min by different authors). We accept this because we key on author
  as well; but reviewer should confirm we're not stripping locale
  markers from the title before shingling.
- **Benchmark-guard escape hatch.** `NO-BENCHMARK-JUSTIFY:` in the PR
  body is a foot-gun. Reviewer should require the justification to also
  land in `docs/plan-*.md` (grep-checked in CI).
- **YouTube CC classification lies.** Uploaders frequently mislabel
  copyrighted material as CC-BY on YouTube. We must **never** promote a
  YouTube-CC record above `License.CC_BY` at ingestion time; downstream
  verification (thumbnail hash vs known-copyright corpora, or manual
  review) is required before any use.
