# Adversarial Plan — 2026-11-12

> Note: no fresh `Adversarial-Agent` plan was posted today, so this plan
> is authored by `Coding-Agent` acting in an adversarial stand-in role.
> It explicitly attacks the three "Risks the next reviewer should
> challenge" that the 2026-06-20 seed plan deferred:
>
> 1. License classification is heuristic and may mislabel non-redistributable Commons uploads.
> 2. Common Crawl JSON-LD blocks frequently lie about `contentUrl`. We must always treat the *page* license, not the embedded video's provider.
> 3. Cooking search terms vary by language — the seed PR shipped English only.
>
> It also hardens two unstated-but-obvious weaknesses:
> 4. The baseline quality score has no *domain-relevance* term — a cat video with a good license and 720p resolution will outrank an on-topic recipe video with no declared resolution.
> 5. We have no notion of *cross-source duplicates*. A single video re-uploaded to Wikimedia Commons and Internet Archive counts twice in `__total__`.

## Hypotheses under test

- **H1 (relevance).** Adding a cheap, metadata-only cooking-relevance signal (multilingual keyword match on title + description + keywords) materially changes the per-source ranking vs. the 2026-06-20 baseline. If it does *not* change the ranking, the baseline weights are already proxying for relevance via `has_steps`/`text_density` and we can skip this component.
- **H2 (language).** A tiny stopword/unicode-range language detector (no new runtime dep) agrees with ground-truth language tags on ≥90% of the Wikimedia + PeerTube fixtures we curate. If it does, we can compute per-language yield without a model.
- **H3 (contentUrl risk).** In the long tail of recipe pages discovered via Common Crawl, many `VideoObject.contentUrl` fields point at commercial platforms (`youtube.com`, `vimeo.com`, `facebook.com/video`, …). These records must *not* be treated as redistributable even if the recipe page itself is CC-licensed. Confirm by adding a fixture that embeds a YouTube video on an otherwise-CC recipe page and showing the record stays `RESTRICTED`.
- **H4 (dedup).** A fingerprint of `(ascii_folded_title_slug, duration_bucket_5s)` collapses the obvious cross-source duplicates introduced by Commons ↔ Archive.org mirrors. Measure dedup rate on a synthetic fixture that intentionally mirrors one record.
- **H5 (ablation discipline).** Running the comparison harness under multiple weight profiles side-by-side (baseline `v1`, re-weighted `v2`, cooking-focused `v2_cooking`) surfaces *which* heuristic a given ranking is actually sensitive to. Committed under `reports/ablate-YYYY-MM-DD.json`.

## Deliverables for `Coding-Agent`

- [ ] `src/specint/quality/language.py` — pure-function `detect_language(text)` returning a BCP-47 code or `None`. Unicode range for CJK/Devanagari; stopword-list for en/es/fr/de/it. Document each list source.
- [ ] `src/specint/quality/relevance.py` — pure-function `cooking_relevance(record)` → float in `[0, 1]` using multilingual seed terms.
- [ ] `src/specint/quality/profiles.py` — named weight profiles (`v1`, `v2`, `v2_cooking`). All sum to 1.0. `score_record(record, profile="v1")` preserves the 2026-06-20 numbers.
- [ ] `src/specint/dedup.py` — `fingerprint(record)` + `dedup(records)` keeping the highest-quality copy per fingerprint. Return stats.

- [ ] `src/specint/compare/ablation.py` — run `run_comparison` under every registered profile and emit a flat list of `(profile, source, …)` rows. Wire into the CLI as `python -m specint ablate`.

- [ ] `reports/compare-2026-11-12.json` — new baseline using profile `v1` (comparable to `baseline-2026-06-20.json`) with updated numbers from new fixtures.

## Out of scope today

- Any additional sources (Vimeo CC, Flickr video, YouTube CC listing API). We will add those once the quality / dedup discipline is stable.
- Actually downloading video frames.
- Any trainable model. All signals must stay metadata-only and pure-function so we can score millions of candidates cheaply.

## What the reviewer should challenge next

- The stopword lists are ~20 words per language; false negatives on short titles will be common. Measure and either expand or switch to `fasttext-langdetect` (new dep) in a future PR.
- `cooking_relevance` currently treats all cooking keywords as equally diagnostic; `fermentation` should weigh more than `food`. Learn weights from the labelled fixtures once we have ≥50.
- Dedup collapses on title+duration, which breaks for re-cut or multi-part videos. Phase-2: perceptual hash on a single mid-video thumbnail.
