# Adversarial-Agent Plan — 2026-08-18

> Follow-up to `docs/plan-2026-06-20.md`. That plan shipped a working
> seed: four adapters, one quality scorer, one comparison harness, and a
> baseline (`reports/baseline-2026-06-20.json`). This plan attacks the
> weakest parts of that baseline and forces the next Coding-Agent PR to
> either beat it or justify why it did not.

## Hypotheses under test

- **H2 (Yield).** Wikimedia Commons *search* under-samples cooking
  footage by 5–10x versus the same-day *category* listings
  (`Category:Videos_of_cooking`, `Category:Cooking_videos`, per-cuisine
  subcategories). If true, adding a category-generator adapter should
  push the wikimedia `n_records` cap way past what the previous baseline
  hit for the same seed terms.
- **H3 (Quality is policy, not fact).** A single fixed
  `WEIGHTS` vector in `quality/metrics.py` conflates three orthogonal
  research questions:
  (a) "can we redistribute?" (license),
  (b) "is it dense procedural supervision?" (recipe steps, verb count),
  (c) "is it high-resolution enough for a world model?" (resolution,
      duration, aspect).
  Fix: `WEIGHT_PROFILES` with at least `default`, `procedural`,
  `resolution`, so every source can be compared under each policy and we
  can see which sources win which policy. This turns quality into a
  systematic comparison, not an unarguable scalar.
- **H4 (Cross-source dedup matters at scale).** The same
  government-funded cooking demo can appear on Internet Archive *and*
  Wikimedia Commons *and* a PeerTube mirror. Naive `n_records` therefore
  over-counts. A deterministic (title-normalised + duration-bucketed)
  dedup pass should cut the __total__ `n_records` on the fixture set by
  a non-trivial amount even at N=8.

## Adversarial questions

1. **Category-vs-search.** For each Commons search term, what fraction
   of the resulting videos are *also* reachable by walking one
   subcategory two levels deep? If the answer is "most", search is
   redundant and we should switch the yield story to category walking.
2. **Metadata signal.** How well does *metadata-only* quality track
   downstream usefulness? We can't answer with real training yet, but we
   *can* insist that a "procedural" profile ranks recipe-step-carrying
   sources (Common Crawl schema.org) above bare Archive.org listings —
   and if it doesn't, the profile is broken.
3. **Provenance under dedup.** When we collapse two records to one, we
   must not silently drop provenance. Every deduped record must retain
   the URL+license of every merged parent.
4. **CI shield.** Coverage on `src/specint/` is currently unenforced.
   Add a `--cov-fail-under` floor so the next Coding-Agent can't quietly
   ship dead code paths.
5. **Repro of yesterday.** Any change to weights or heuristics must
   emit a new dated report under `reports/` next to the old one — never
   overwrite. Older reports are the only ground truth we have.

## Concrete deliverables for `Coding-Agent`

- [ ] `src/specint/quality/metrics.py`
  - Introduce `WEIGHT_PROFILES: dict[str, dict[str, float]]` with
    `default`, `procedural`, `resolution` keys. Keep `WEIGHTS` as an
    alias for `WEIGHT_PROFILES["default"]` for backward compatibility.
  - Add new metadata-only components:
    - `language_confidence` — deterministic stopword-based detector
      that returns 1 if `language` is set OR title/description hits a
      known English/French/Spanish stopword threshold, else 0.
    - `procedural_density` — hits against a small verb list
      (`chop, slice, mix, saute, bake, roast, whisk, ...`) over
      `recipe_steps + description`, normalised.
    - `recency` — linear decay from `published_at` (1.0 today → 0 at
      15 years old). None → 0.5 (unknown, not penalised nor rewarded).
    - `aspect_ratio_ok` — 1.0 if width/height in [1.3, 2.4], else 0.5.
  - `score_record(record, profile: str = "default")`.
- [ ] `src/specint/quality/dedup.py` (new)
  - `normalize_title(str) -> str`.
  - `duration_bucket(seconds) -> int` (30s buckets, `None` → -1).
  - `dedup(records) -> tuple[list[VideoRecord], list[DedupCluster]]`
    where `DedupCluster` carries the merged parents' URLs and licenses.
- [ ] `src/specint/sources/wikimedia_category.py` (new)
  - `WikimediaCommonsCategorySource(slug="wikimedia_category")` using
    `generator=categorymembers`. Parse is fixture-testable; live search
    walks a configurable category list.
  - Register in `sources.__init__.REGISTRY`.
- [ ] `src/specint/records.py`
  - `BenchmarkResult.profile: str = "default"` (backward-compatible).
- [ ] `src/specint/compare/harness.py`
  - `run_comparison(query, by_source, profile="default")` and
    `run_all_profiles(query, by_source)` → dict[profile → rows].
  - Emit dedup-aware `__unique_total__` row alongside `__total__`.
- [ ] `src/specint/cli.py`
  - `--profile {default,procedural,resolution,all}`.
- [ ] Tests
  - `tests/test_quality_profiles.py` — profile "procedural" ranks
    Common Crawl above Archive.org on the fixture set.
  - `tests/test_dedup.py` — synthetic dupes across two sources collapse
    and preserve both parent URLs.
  - `tests/test_sources_wikimedia_category.py` — fixture-driven parse.
  - Extend `tests/test_e2e_compare.py` to iterate profiles.
  - Parametric license classifier tests
    (`tests/test_license_classifier.py`).
- [ ] CI
  - `pytest --cov=specint --cov-fail-under=85`.
  - Comparison job runs `--profile all` and stores the artifact.
- [ ] Report
  - Commit `reports/compare-2026-08-18.json` covering every registered
    source under every profile.

## Explicit metric to beat

Compared to `reports/baseline-2026-06-20.json` (mean_quality per source,
default profile):

- wikimedia 0.62 → **must be >= 0.62**.
- peertube 0.57 → **must be >= 0.57**.
- common_crawl 0.53 → **must be >= 0.53**.
- archive_org 0.36 → **must be > 0.36** *or* documented as expected
  because the new `recency` component penalises undated Internet Archive
  uploads.

If a number regresses, the PR description must say **why** the regression
is informative (e.g. "recency now punishes undated items, which is
correct behaviour and drops archive_org by X").

## Out of scope today

- Live network calls (still fixtures only).
- Distributed crawling.
- Multilingual seed expansion beyond the stopword detector's
  English/French/Spanish coverage.
- Actual video download / frame extraction.

## Risks the next reviewer should challenge

- Stopword-based language detection is crude; false positives on tiny
  titles. Mitigation: threshold requires >= 2 stopword hits.
- Category-walking on Commons can explode combinatorially. Mitigation:
  hard depth+width caps in the adapter.
- Dedup key (normalised title + duration bucket) will over-merge
  templated titles ("Cooking, part 1"). Mitigation: require author or
  duration to differ before a cluster > 3 items is allowed.
