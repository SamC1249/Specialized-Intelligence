## TL;DR

The 2026-06-20 baseline is a **fixture-only** ranking of four sources.
It is not falsifiable: the fixtures have 1–3 records per source, so any
"mean quality" gap is noise. Worse, three structural biases mean the
current ranking is *predictable from the schema of each API*, not from
the actual quality of the underlying video corpus. We fix that today.

## Standing hypotheses (from 2026-06-20)

- **H1** (permissive-cooking Pareto). Still worth testing, but not
 falsifiable at N=8 records total across sources.

## New hypotheses under test

- **H2 (yield ceiling).** Wikimedia Commons is **hard-capped** at
 ~O(10²)–O(10³) cooking videos globally, on the order of 100 hours,
 dominated by `Category:Videos_of_cooking` (74 files),
 `Category:Home_cooking` (190 files), and `Category:Cooking` (860
 files, most of which are stills). This is smaller than a single
 dedicated academic dataset (CaptainCook4D, 94.5 h, Apache-2.0). Test
 by category enumeration, not keyword search.
- **H3 (schema-availability bias).** The current `quality/metrics.py`
 scorer punishes sources that structurally do not populate
 `width/height`. `archive_org` returns no resolution field; `peertube`
 returns `resolution.id` (height only); only `wikimedia` and
 `common_crawl` populate both. Therefore the current mean_quality
 ranking (wikimedia > peertube > common_crawl > archive_org) is
 partially explained by field availability, not video quality. Prove
 with a synthetic test: an archive_org record that *is* 1080p scores
 below a peertube record with identical license and duration, purely
 because of schema conventions.
- **H4 (redistributable-yield beats mean-quality).** The metric we
 actually care about for a training corpus is
 `Σ license_clean · duration_s` (redistributable seconds), not mean
 quality. Baseline: currently 6/8 records license-clean, ~2.5 h total
 in fixtures. Any new adapter must publish this number.
- **H5 (Web Data Commons dominates Common Crawl).** Webdatacommons.org
 already extracts every `schema.org/VideoObject` and `schema.org/Recipe`
 block from every Common Crawl snapshot since 2013 and republishes them
 as N-quads. That is at least 4 orders of magnitude cheaper to ingest
 than iterating WARCs ourselves, and the `common_crawl` adapter is
 currently synthetic (no `search()` implementation). We should ship a
 `webdatacommons` adapter and *deprecate* live WARC iteration.
- **H6 (source dedup is load-bearing).** The same video is regularly
 mirrored to multiple sources: Blender Foundation shorts appear on
 both `video.blender.org` (PeerTube) and Wikimedia Commons; USDA and
 NIH cooking-safety videos appear on both archive.org and Commons.
 Without dedup, `unique_authors` and per-source counts double-count.
 No dedup exists today.

## Attacks on our own system

1. **The current baseline is unfalsifiable.** N=8 records, all
 fixtures. Any regression would be attributed to noise. We need a
 *gold set* of hand-verified license-clean cooking videos so we can
 measure recall of each source, not just their self-reported
 metadata.
2. **`extractor_git` is hardcoded to `"dev"`.** `Provenance` claims to
 pin the exact extractor commit; today it lies. Fix: read
 `SPECINT_GIT_SHA` from the environment (CI already knows it) or fall
 back to `subprocess.check_output(["git", "rev-parse", "--short",
 "HEAD"])` at import time.
3. **License heuristics are string-based.** `wikimedia._coerce_license`
 substring-matches; `"BY-NC-ND"` returns `RESTRICTED` (good), but
 `"BY-ND"` returns `RESTRICTED` and `"BY-SA"` returns `CC_BY_SA` — and
 `"BY 4.0"` (no dash) currently falls through to `UNKNOWN`. Ship a
 table-driven license classifier and a per-classifier fixture set.
4. **`SPECINT_RUN_INTEGRATION=1` is dead code.** Not exercised in CI.
 Add a nightly job that runs integration tests with
 `--continue-on-error` and uploads a diff of what live search returns
 vs. the last fixture, so we notice upstream schema changes.
5. **Coverage isn't enforced.** CI prints coverage but never fails on
 it. Set a floor at 90% on `src/specint/records.py`,
 `quality/metrics.py`, and `compare/harness.py` (the pure-function
 core); leave adapters best-effort.
6. **`docs/artifacts/` was never created.** AGENTS.md refers to
 `Reviewer-Agent` in the future tense but there's nowhere to park
 paper notes. Fix today.

 mean_quality, and the plan-2026-08-19 report shows a *bigger* delta

## Risks the next reviewer should challenge

- **Adversarial tests should not paper over bugs.** `xfail` is a
 tracking tool, not a mute button. If `test_adversarial_quality_bias`
 flakes to `xpass`, that's an unhandled improvement — investigate,
 don't just remove the marker.
- **Web Data Commons snapshots lag ~monthly.** For freshness we still
 need direct WARC iteration eventually — do not delete
 `common_crawl.py`.
- **License-string classification is intrinsically heuristic.** We
 should default to `License.UNKNOWN` in every ambiguous case and rely
 on the harness to exclude UNKNOWN from training corpora, which the
 aggregation already does.
