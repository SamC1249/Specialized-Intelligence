# Adversarial-Agent Plan — 2026-09-13

> No `docs/plan-*.md` file existed between 2026-06-20 and today. This plan
> carries forward the unresolved risks/follow-ups from
> `docs/plan-2026-06-20.md` and picks the two highest-leverage attacks on
> the current baseline.

## Where we stand

- Baseline (`reports/baseline-2026-06-20.json`) ranks fixture yields by
  mean quality: `wikimedia 0.62 > peertube 0.57 > common_crawl 0.53 >
  archive_org 0.36`.
- The quality scorer is metadata-only with 5 hand-weighted components
  (`license_clean 0.35 / duration 0.15 / resolution 0.20 / text_density
  0.15 / has_steps 0.15`). There is exactly one weight vector; we have
  never tested whether it is a good one.
- We have no way to detect cross-source duplicates, so the aggregate
  `__total__` row over-counts identical videos that federated PeerTube
  instances or Common Crawl pages mirror from Wikimedia / Archive.
- CI runs the harness but does not report Pareto trade-offs between
  competing quality policies, so we have no defensible way to say "policy
  A is better than policy B on this fixture set."

## Hypotheses under test

- **H2 (Procedural density).** Metadata-only signals — recipe-step count,
  imperative-verb hits in title/description/steps normalized by declared
  duration — Pareto-dominate the current `has_steps + text_density`
  proxies for downstream procedural-supervision usefulness, at fixed
  license-cleanliness.
- **H3 (Policy sweep).** No single scalar quality score is right for
  every downstream training run. A registered set of *named
  `QualityPolicy` weight vectors*, swept over the same fixture corpus,
  gives us a Pareto frontier of `(mean_quality, n_license_clean,
  procedural_density_p50)`. That frontier is the honest artifact — not a
  single number.
- **H4 (Cross-source dedup).** A conservative
  `(normalized_title, duration_bucket)` blocking key surfaces enough
  cross-source collisions on the current fixtures that the `__total__`
  row over-counts by a measurable margin. If it doesn't, we still ship
  the tool so the number is auditable, not asserted.

## Deliverables for `Coding-Agent`

- [ ] `src/specint/quality/procedural.py` — pure, offline procedural-
      density scorer (imperative-verb lexicon + step count / duration).
      **No** ML models; deterministic + testable.
- [ ] `src/specint/quality/policies.py` — `QualityPolicy` (name, weight
      map). Ship at least: `baseline`, `procedural-heavy`,
      `license-strict`.
- [ ] `src/specint/quality/metrics.py` — refactor `score_record(s)` to
      accept an optional `QualityPolicy`; default preserves current
      behavior exactly (tests must still pass).
- [ ] `src/specint/compare/dedup.py` — cross-source dedup with a
      `DedupReport` model.
- [ ] `src/specint/compare/sweep.py` — runs the comparison harness for
      every registered policy; emits a JSON with per-policy rows plus a
      Pareto frontier subset and the `DedupReport`.
- [ ] `python -m specint sweep --fixtures` CLI + `--output` argument.
- [ ] Tests:
  - `tests/test_procedural.py`
  - `tests/test_policies.py`
  - `tests/test_dedup.py`
  - `tests/test_sweep.py`

- [ ] `reports/baseline-2026-09-13.json` — same fixtures, new metrics

- Multilingual language detection — still a follow-up.
- Real Common Crawl WARC iteration — still a follow-up.

## Risks the next reviewer should challenge

- Imperative-verb lexicons are English-only and Western-cuisine-biased.
  Mitigation: keep the lexicon in a single file that a multilingual PR
  can extend, and treat "verb hits" as a *density* (per second) so short
  fixtures are not penalized just for being short.
- `QualityPolicy` weights can be gamed. Mitigation: every sweep result
  is committed under `reports/` and any future weight change must beat
  the current frontier on at least one axis without regressing the
  others.
- Dedup blocking is intentionally conservative (title + duration bucket)
  and will miss re-cuts. That is acceptable for a v1: false positives
  are worse than false negatives here.
