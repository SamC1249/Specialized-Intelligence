The bootstrap PR shipped the scaffolding: a canonical schema, four

## Hypotheses under test

> **H2.** The current metadata-only quality score is *dominated by
> `license_clean`* (weight 0.35) and *`resolution`* (0.20). A record
> with CC-BY and 1080p auto-scores ≥ 0.55 even if its title is empty
> and it has zero recipe steps. We can construct an adversarial
> fixture proving this and demonstrate that a small
> `text_density_min` gate on `title+description` moves mean quality
> *up* on the same fixtures.

> **H3.** Our license classifier is regex-fragile. Common Commons
> license strings that we have **never seen** (`"Attribution-
> NonCommercial-ShareAlike 4.0 International"`, `"CC BY-NC 4.0"` with
> unicode NBSP, `"cc-by-nc-nd-2.5"`, `"GFDL 1.2"`) will
> mis-classify or fall through to `UNKNOWN` when they should be
> `RESTRICTED`. A table-driven test can pin all of these down.

> **H4.** The comparison harness is not invariant under **record
> duplication**. If the same PeerTube video is federated across two
> instances, we count it twice and inflate `n_records`,
> `total_duration_s`, and `unique_authors`. Content dedup is out of
> scope for a metadata-only tier, but **URL-canonicalization dedup is
> not** — same `id` across two sources should collapse to one, and we
> currently don't check.

> **H5.** `python -m specint compare --fixtures` produces an all-zeros
> report because the CLI never actually loads fixture data — the e2e
> test loads fixtures directly, bypassing the CLI. This means our CI
> job "E2E compare (fixtures)" claims coverage it does not have. This
> is a **process-integrity bug**, not a data-quality bug, and should
> be filed and fixed.

> **H6.** Provenance is not actually reproducible: `extractor_git`
> defaults to `"dev"` and no code path ever writes the real git SHA.
> AGENTS.md rule 2 ("provenance is mandatory") is technically
> violated on every record we produce.

> **H7.** Yield ceilings are much lower than we implied. Wikimedia
> Commons `Category:Videos_of_cooking` has ~75 files today,
> `Category:Videos_of_food_preparation` has ~48, and the deepest
> subcategories add at most low hundreds more. The realistic clean
> cooking-video yield from Commons is in the **hundreds of hours,
> not thousands** — we should say so publicly instead of implying
> internet-scale volumes.

## What I actually shipped today (Adversarial-Agent)

Deliverables in this PR:

1. **`docs/artifacts/` seeded** with five annotated summaries
   (RecipeGen, DenseStep2M, RECIPE-RL, Panda-70M filters,
   WBench/WorldPrediction). Each names the exact repo module to touch.
2. **Adversarial test suite** codifying invariants that today's code
   accidentally satisfies but has no guard against regressing:
   - `tests/test_license_classifier_edges.py` — table-driven cross-
     adapter classifier truths (CC-BY-NC / CC-BY-NC-SA / CC-BY-ND /
     GFDL / whitespace variants → `RESTRICTED`; canonical CC0 / CC-BY /
     CC-BY-SA / PD → correct enum). Locks in H3.
   - `tests/test_provenance_and_media_url_gating.py` — every record
     across every fixture carries a non-empty provenance and never
     leaks a `media_url` when the license is not redistributable.
     Locks in the license-gating half of H6.
   - `tests/test_harness_determinism.py` — running `run_comparison`
     twice on the same input yields byte-identical JSON. Guards
     silent ordering drift.
   - `tests/test_harness_id_dedup.py` — if the same `VideoRecord` is
     handed to the harness under two source slugs, no source's
     `n_records` double-counts within itself; documents H4's current
     status.
   - `tests/test_cli_fixtures_smoke.py` — invokes `python -m specint
     compare --fixtures` in-process and asserts the CLI produces a
     valid JSON report. This test **passes today** but includes an
     `xfail` sub-check asserting the CLI actually returns non-zero
     `n_records` — this xfail is the codified form of H5 and is the
     signal for Coding-Agent to fix the CLI.
3. **CI + pre-commit hardening**:
   - New pre-commit hook `detect-adversarial-todo` warns on any
     unresolved `SPECINT-ADVERSARIAL:` marker in tracked files.
   - New CI job step: `python -m specint sources` must list all four
     registered slugs (guards against silent adapter deregistration).
   - Existing e2e job unchanged; a follow-up will replace the empty
     `--fixtures` CLI output with a real fixture-backed report once
     H5 is fixed.

Nothing above changes the current baseline JSON. This is deliberate:
adversarial invariants should pin behavior, not shift it.

## Concrete deliverables for `Coding-Agent` (in priority order)

### P0 — Correctness / integrity

- [ ] **Fix H5.** In `src/specint/cli.py`, when `--fixtures` is passed,
      load each adapter's checked-in fixture from `tests/fixtures/`
      (or a new `data/fixtures/` mirror) and run its `parse()` — so the
      CLI produces the same non-zero report the e2e test does. Then
      flip the xfail in `tests/test_cli_fixtures_smoke.py` to a hard
      assert.
- [ ] **Fix H6.** Add a `specint._version.get_extractor_git()` helper
      that reads `GITHUB_SHA` first, falls back to `git rev-parse
      --short HEAD`, and stamps every `Provenance` at record-creation
      time. Delete the `"dev"` default.
- [ ] **Address H4 minimally.** Add `run_comparison` de-duplication by
      `VideoRecord.id` *within each source slug*. Cross-source dedup
      stays out of scope until we have URL canonicalization
      (see P2).

### P1 — Quality of ranking

- [ ] **Add `text_density_min` gate** (H2). If
      `len(title) + len(description) < 40 chars`, quality is clamped
      to `min(quality, 0.4)` regardless of license. Add a fixture
      with a 1080p CC-BY record that has an empty title to lock in
      the behavior.
- [ ] **Add `step_density` component** (per `docs/artifacts/2026-07-
      14-recipegen.md`): `n_steps / max(1, duration_min)`; folded
      into `WEIGHTS` with weight 0.10, replacing binary
      `has_steps` (keep `has_steps` as a fallback when duration is
      unknown).
- [ ] **Add `negative_signals` module** (per
      `docs/artifacts/2026-07-14-panda70m-filters.md`) with detectors
      for slideshow/screen-recording/reaction/PIP patterns in
      titles. Each detector emits a tag and a documented penalty.

### P2 — Coverage / yield

- [ ] **Common Crawl CDXJ probe adapter.** Real `search()` for
      `CommonCrawlRecipeSource` using `cdx_toolkit` against a small
      set of known recipe hosts we've already vetted for
      redistributable content (Wikibooks Cookbook is the safe seed:
      CC-BY-SA 3.0). Do not touch WARC bodies in this PR; use the
      CDXJ metadata only for the first slice.
- [ ] **Wikimedia Commons category walker.** Add a category-based
      enumerator using `list=categorymembers&cmtype=file` starting at
      `Category:Videos_of_cooking` and recursively into
      subcategories. Deduplicate by `pageid`. Compare yield vs
      `generator=search`; publish `reports/wikimedia-category-vs-
      search.json`.
- [ ] **YouTube Data API adapter (URLs only, no media).** Gated on
      `YOUTUBE_API_KEY` env var; forced `videoLicense=creativeCommon`
      and `type=video`. Cost 100 units per `search.list` call;
      budget-tracking helper mandatory. Emit records with
      `license = License.CC_BY` (v3 default), `media_url = None`,
      and honest provenance. Add a "YouTube URL is a pointer, not a
      mirror" note in `db_structured.md`.

### P3 — Discipline / meta

      Coding-Agent can add fields without breaking existing
      `reports/*.json` consumers.

## Out of scope today (explicit non-goals)

- Downloading any video bytes. Everything remains URL+metadata.
- Ego4D / Ego-Exo4D / RecipeGen adapters — these are
  license-restricted or non-commercial and must be reference-only.
  See `docs/artifacts/2026-07-14-recipegen.md` and the caveat in
  `docs/artifacts/2026-07-14-wbench-worldprediction.md`.
- Perceptual video hashing (videohash / BK-tree). Requires frame
  decode; belongs in the future frame-sampled tier.
- Distributed / async crawling. Single-process remains fine until
  P2 adapters exist.

## Risks the next reviewer should challenge

1. **"Metadata-only will always be enough."** It won't. WBench's five
   evaluation dimensions include physics compliance and inter-turn
   consistency, both unreachable from titles. We need to plan the
   frame-sampled tier now, not later — even if the first
   implementation is a manual notebook rather than a scheduled job.
2. **"CC-BY is safe."** CC-BY 4.0 requires attribution *in a manner
   specified by the licensor*. Our schema stores `author` but no
   downstream code enforces attribution during corpus export.
3. **"Yield estimates from listing APIs generalize."** They don't.
   Wikimedia Commons search is title-biased; Category enumeration is
   the ground truth. Report both.
4. **"Live PeerTube instances are stable."** They aren't. Any live
   adapter must degrade gracefully when an instance is offline and
   record the outage in provenance, not just swallow the exception.
5. **"YouTube CC search is fine because the license claim is
   real."** It's fine for URL/metadata harvest, but the actual CC
   version is CC-BY 3.0 (unattributed on YouTube's side), and the
   creator can retroactively change the license. Any harvested
   record needs a re-verify pass before being promoted to training.

## Metrics we will watch across daily runs

Track these in `reports/compare-YYYY-MM-DD.json`:

- `n_records`, `n_license_clean`, `total_duration_s` per source and
  aggregate.
- `mean_quality`, `p50_quality`, `p90_quality`.
- (New, once P1 lands) `n_verifier_passed`, `n_penalty_tagged`.
- (New, once P2 lands) `n_deduped_removed` (cross-source ID collision
  count).

The comparability rule stands: **any PR that changes a scorer or
adapter must produce a new `reports/*.json` and beat the prior
baseline on at least one of the above without regressing others by
more than 5%**, or explain in the plan why the regression is
informative.
