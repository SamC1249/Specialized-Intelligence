# Vimeo Creative Commons Collection (V3C) — What We Can And Can't Ingest

**Citations.**

- Rossetto et al., "V3C — A Research Video Collection",
  arXiv:1810.04401. Origin paper: 28,450 Vimeo CC videos, ~3,800 hours,
  Vimeo categorization used to filter for "real-world" content.
- TRECVID 2025 Guidelines
  (<https://www-nlpir.nist.gov/projects/tv2025/data.html>) — V3C1
  (7,475 videos / ~1,000h), V3C2 (9,760 / ~1,300h) both released only to
  TRECVID active participants under signed NIST data-use agreement.
- Original NIST V3C data-use agreement text
  (<http://www-itec.aau.at/~klschoef/VBS2019/V3C_Org.Form.txt>).

## One-line summary

V3C is by far the largest ready-made corpus of *Vimeo-hosted*
Creative-Commons video (thousands of hours). The *videos themselves*
require signing a NIST participant agreement, but the shot-boundary
manifests and per-video Vimeo IDs+license metadata are public research
artefacts we can legally consume.

## Why this matters for us

`AGENTS.md` allowlist covers Wikimedia, Internet Archive, PeerTube,
Common Crawl and CC-BY YouTube. Vimeo CC is a natural neighbour and is
already curated for research — we shouldn't skip it just because the
media file itself is form-gated. The metadata is the point: legally-
provable Vimeo video IDs whose owner-selected license is CC-BY / CC0.

Concrete legal analysis (not legal advice, but the operating stance):

- The V3C paper's raw list of Vimeo IDs and license classifications is
  a bibliographic reference; enumerating "video X is CC-BY-licensed on
  Vimeo" is not itself a copyright act.
- Fetching each Vimeo page's public oEmbed metadata
  (<https://vimeo.com/api/oembed.json?url=…>) is API-explicit,
  no-auth-required, and returns title + description + thumbnail URL +
  duration. Same public API a WordPress embed uses.
- We can therefore build a metadata-only adapter that lists CC-BY /
  CC0 Vimeo videos with URL + license + attribution, *without* ever
  triggering NIST's signed-agreement scope.

## What to steal

1. **Vimeo's licence categorisation.** V3C's paper defines the
   subcategory allowlist ("Personal", "Documentary", "Sports",
   plus filtered sub-categories under others). Ship the same
   allowlist as a `docs/sources.md` fixture — future adapters can
   filter by it.
2. **Shot boundary manifests as free supervision.** NIST published
   per-video master shot boundary files. Once we have a Vimeo adapter,
   the boundaries give us the free-of-charge PySceneDetect equivalent
   for the *V3C subset* without needing to run PySceneDetect ourselves.
3. **Explicit "media is out of scope" pattern.** Our record contract
   already sets `media_url = None` on non-redistributable records; V3C
   is a perfect stress case (the *video* is out of scope, the
   *metadata* is not). Add a V3C fixture that verifies our invariants
   under this exact condition.

## What to not steal

- **The bulk V3C1/2/3 tarballs.** Requires signed NIST agreement +
  university-of-Basel-provenanced files. Never mirror.
- **Vimeo API scraping without oEmbed.** Vimeo's search API requires
  auth and rate-limits aggressively; use only oEmbed for metadata,
  and only when we already have a video ID from a public source (V3C
  manifest, a user-provided URL, etc.).
