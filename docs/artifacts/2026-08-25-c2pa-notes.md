# Minimal C2PA-shaped provenance

Author: Coding-Agent · Date: 2026-08-25

C2PA (Coalition for Content Provenance and Authenticity) v1.4 defines a
manifest format that bundles:

- one or more **assertions** (`c2pa.hash.data`, `c2pa.hash.collection.data`,
  `c2pa.actions`, `stds.exif`, ...),
- a **claim** signed with an X.509 certificate,
- a **signature** and an optional timestamp.

We don't need the crypto today; we do need the *shape* so we can adopt
C2PA later without a schema migration.

## What we adopt now

`Provenance` (see `db_structured.md`) already carries the fields C2PA
assertions demand:

| C2PA assertion field         | Provenance field     |
| ---------------------------- | -------------------- |
| `c2pa.hash.data.exclusions[].hash` | `raw_sha256`     |
| `c2pa.actions[].parameters.instanceId` | `id` on the record |
| `c2pa.claim_generator`       | `extractor` + `extractor_git` |
| `stds.exif.DateTimeOriginal` | `published_at`       |
| `c2pa.provenance_hint`       | `url`                |
| `c2pa.assertions.ingredients[].url` | `license_url` |

## What we defer

- **Cert issuance.** A C2PA claim must be signed by an accepted CA. No
  budget or CA relationship yet.
- **Manifest bundling.** We store one flat `Provenance` per record; a
  real C2PA export would zip the manifest into the media container.
- **Ingredient chain.** For derived assets (frames extracted from a
  source clip), C2PA wants an `ingredients` list; we handle that only
  when we start extracting frames.

## Migration outline

When we adopt C2PA fully:

1. Add a `signature: bytes | None` field to `Provenance` (JSON-encoded
   COSE_Sign1).
2. Ship a `c2pa/manifest.py` writer that takes a `Provenance` and a
   media path and emits a `.c2pa` sidecar.
3. Gate any external export behind `provenance.signature is not None`.
