# docs/artifacts/

Research notes on papers, blog posts, and open pipelines that inform
our own data-collection design. One file per source, dated `YYYY-MM-DD`.

Format for each file:

- One-line summary at the top.
- "Why this matters for us" section (concrete, not abstract).
- "What to steal" section — the pieces we should adopt or adapt.
- "What to *not* steal" section — the pieces that violate our
  legal-source rule or add GPU dependencies we can't ship in CI.
- Full citation with URL.

Artifacts are inputs to `docs/plan-YYYY-MM-DD.md`; treat them like a
lab notebook, not documentation. Newer artifacts may contradict older
ones.
