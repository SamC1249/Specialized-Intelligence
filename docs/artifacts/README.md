# docs/artifacts — research notes

Short, dated papers-and-blogs notes that back the daily adversarial
plans in `docs/plan-*.md`. Every artifact must:

1. Name its sources (paper, arXiv id, URL, retrieval date).
2. Explain, in one paragraph, *why* the artifact matters for our
   frontier-data-collection goal (not "what the paper says").
3. Map to at least one concrete deliverable in a plan (by filename
   + section) so the Coding-Agent has a direct execution target.
4. State a **falsifier** — the observation that would prove the
   direction wrong. If we can't name one, the artifact is a hunch,
   not a research note.
