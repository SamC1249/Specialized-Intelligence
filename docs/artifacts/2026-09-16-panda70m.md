# Panda-70M — quality-first video-caption pipeline

- Chen et al. CVPR 2024.
  [arXiv:2402.19479](https://arxiv.org/abs/2402.19479) ·
  [code](https://github.com/snap-research/Panda-70M/).

## What they built

Panda-70M starts from **3.8M HD-VILA-100M long videos**, runs a
semantics-aware **shot-boundary split** (PySceneDetect →
ImageBind-embedding merge → 5-second fallback cuts), scores each clip
with **Max Running LPIPS** to reject semantically-inconsistent clips,
throws out clips <2 s or with too-small motion (‖ΔImageBind‖ ≤ 0.15),
caps clips at 60 s, and deduplicates by keeping only clips whose
average ImageBind feature is >0.3 Euclidean from every prior clip in
the same source video.

They then run **8 vision-language teacher models** to produce candidate
captions, and fine-tune a **UMT retrieval model on 100k human-preferred
captions** to pick the best one. Their releases include a
"desirability" filter with 6 categories (`desirable`,
`0_low_desirable_score`, `1_still_foreground_image`,
`2_tiny_camera_movement`, `3_screen_in_screen`,
`4_computer_screen_recording`).

## What we can steal

- **The quality axes are the right axes.** For our recipe/cooking
  corpus we should reject `still_foreground_image` (recipe cards),
  `tiny_camera_movement` (talking-head vlogs where the actual cooking
  is off-screen), `screen_in_screen` (reaction videos), and
  `computer_screen_recording`. All four are cheaply detectable from
  metadata (aspect ratio, keyword presence "reaction", MIME type
  gif/webp) or from a *first frame* — no full download required for
  our current stage.
- **LPIPS-style semantic-consistency budgets** map onto text-only
  proxies at the metadata stage: reject records whose title/description
  language differs from `SourceQuery.language`, or whose declared
  category flips mid-record (Common Crawl `Recipe` schema with a
  totally unrelated `VideoObject`).
- **Sample-cap per source video (Panda keeps ≤ 3 clips/source).** For
  us the analogous rule is: **≤ K records per `author`** to prevent
  one prolific uploader dominating.
- **Retrieval-based curation via clustering.** V-JEPA 2 (see the
  V-JEPA note) uses this idea to sample YT1B against a target
  distribution defined by Kinetics + SSv2 + COIN + EpicKitchen. Our
  cheap version: cluster candidate records by `TF-IDF(title +
  description + recipe_steps)` and sample uniformly across clusters
  when building a training slice.

## What we must *not* copy

- Panda-70M's *videos* come from HD-VILA-100M, i.e. YouTube. **Not on
  our allowlist.** The pipeline is fair game as a design template, the
  media URLs are not.
- The captioning teachers are proprietary/commercial (or heavy). We
  should stage a lightweight open-weights alternative (e.g. one small
  VLM) later, and only run it on records already filtered by
  metadata.

## Implementation hooks

- `src/specint/quality/metrics.py` → new heuristics:
  `_score_not_reaction` (penalize keywords like "reaction",
  "commentary"), `_score_not_recipe_card` (penalize if
  `recipe_steps` present but declared `duration_s < 30`), and
  `_score_aspect_ratio` (reject width/height ratios far from 16:9 for
  procedural footage).
- `src/specint/compare/harness.py` → aggregate stat
  `dominant_author_share` (max author's share of records); we should
  publish this per source so we can catch mode collapse early.
- New module `src/specint/curation/cluster.py` → TF-IDF + KMeans (pure
  scikit or a hand-rolled hashing vectorizer if we want to keep deps
  small) with a deterministic seed, used by the CLI's future
  `python -m specint curate --k 128` command.
