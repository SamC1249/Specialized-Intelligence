## Where we are

- Baseline: `reports/baseline-2026-06-20.json` scores our 4 offline
  adapters on 8 fixture records (wikimedia > peertube > common_crawl >
  archive_org by `mean_quality`). Everything downstream must beat that
  number on the same fixtures.
- We are still 100 % metadata-only. No media downloaded, no dedup, no
  language coverage beyond English, no yield estimate against any real
  upstream (only fixtures).
- CI runs pytest + ruff + mypy-best-effort on 3.11/3.12. Pre-commit runs
  ruff, EOF/whitespace, `check-added-large-files`, and pytest on push.
  There is no lint gate against ToS-violating hosts, and no CI enforcement
  that reports never contain `License.RESTRICTED` records.

## Hypotheses under test today

- **H2. License-lint > README warnings.** A source-code-level policy
  linter that greps for a blocklist of ToS-hostile hosts and asserts that
  every committed `reports/*.json` row has a redistributable license will
  catch more regressions than any amount of AGENTS.md text. Prove it by
  shipping the linter, running it in CI, and verifying it rejects a
  synthetic bad row in a unit test.
- **H3. Duplicates are already ≥5 % of yield.** Wikimedia and Common
  Crawl frequently reference the same media (Commons hosts the file,
  recipe blogs embed it). A trivial `dedupe_by_id_and_title` pass over the
  current 8-record fixture set will already collapse ≥ 1 pair. If it
  doesn't, our fixtures are unrealistically clean and the adversarial
  reviewer must expand them.
  - **Result:** `reports/baseline-dedupe-2026-07-13.json` shows 0 records
    collapsed on the current 8-record fixture set. **H3 falsified on
    fixtures** — but this points at a testing-surface problem, not a
    real-world one. Follow-up ticket: `Coding-Agent` must add a
    cross-source dup fixture (e.g. a Common Crawl `contentUrl` pointing
    at the same Commons `.webm` we already ship under `wikimedia/`) and
    prove non-zero collapse against it in a new e2e test.
- **H4. `videoLicense=creativeCommon` on YouTube is small but well-lit.**
  The YouTube Data API returns a `videoLicense` field; filtering to
  `creativeCommon` is explicitly allowed by ToS as a metadata-only query.
  Stub the adapter today (no network) so we can measure yield next.
- **H5. Motion-heavy pretraining wants short diverse clips, not long
  ones.** V-JEPA 2 pretrains on 16-frame, 256²-resolution windows.
  Rewarding 5-minute clips (our current sweet spot) is arguably wrong for
  the *pretraining* mode; it may be right for the *evaluation* mode. Split
  quality into `mode="jepa"` vs `mode="eval"` in a follow-up PR and
  measure delta on the fixture baseline.

## Out of scope today

- Any actual video-frame download.
- Any YouTube endpoint other than `search.list?videoLicense=creativeCommon`.
- Any dataset that requires signing a license (Ego4D, EPIC-KITCHENS).
  Those violate constraint #1 in `AGENTS.md`.

## Risks a future reviewer must challenge

- **Policy-linter false negatives.** The domain blocklist is
  necessarily incomplete. Track FN rate by adding a red-team fixture
  every time we find one in the wild.
- **`dedupe_by_id_and_title` will over-collapse.** Two genuinely
  different recipes titled "Chocolate Cake" from different authors would
  merge. Mitigation: require author *or* URL to also match. Test both.
- **Nightly integration job leaks.** It must fail closed when
  credentials aren't set. Verify with a scheduled dry-run job that only
  prints "SKIPPED" until we opt in.
