# Adversarial-Agent Plan — 2026-07-13

## Where we are

The 2026-06-20 bootstrap shipped four adapters, a metadata-only quality
scorer, a comparison harness, and a fixture-driven CI. The baseline in
`reports/baseline-2026-06-20.json` ranks

```
wikimedia 0.62 > peertube 0.57 > common_crawl 0.53 > archive_org 0.36
```

Anyone reading that ranking should immediately push back on it. Every
number in it is fixture-limited — three docs from `archive_org`, one from
`common_crawl`. A single unlucky fixture drags a source's mean. We do not
have (a) a way to know whether records collected by two adapters are
actually the *same* physical asset, (b) a defensible quality signal
beyond duration/resolution/text-length, or (c) any evidence that our
weight vector is not overfit to what the seed fixtures happen to contain.

## Hypotheses under test

> **H2. Cross-source deduplication changes the ranking.** Wikimedia
> Commons videos are frequently mirrored on Internet Archive, and both
> get re-embedded on recipe blogs indexed by Common Crawl. If we
> aggregate license-clean *unique-asset* yield instead of raw record
> counts, the source ordering will shift. Falsifiable: run the harness
> with and without dedup on the fixtures and inspect the delta.

> **H3. Metadata language ID beats blind English seeding.** Adding a
> `language` component to the quality score, driven by a tiny
> character-trigram detector, will (i) surface genuinely multilingual
> corpora on Commons/PeerTube and (ii) reduce the proportion of records
> that end up with `language=None` after parsing. This is a prerequisite
> for the multilingual work called out in the 2026-06-20 risks section.

> **H4. Procedural density is the killer signal for world-model
> training.** Recipes are the only source that comes with structured
> step text via `schema.org/Recipe`; a step-count component in the
> quality scorer should let a well-tagged Common Crawl recipe outrank a
> silent Commons B-roll clip of the same duration. If procedural
> density does *not* move the needle, our fixtures are wrong, not the
> heuristic.

> **H5. YouTube's `videoLicense=creativeCommon` filter is a legitimate
> long-tail. It's on the AGENTS.md allowlist but has no adapter yet.
> The parse layer must be shippable today even without a live API key —
> the adapter should be entirely fixture-driven for tests, and only the
> `search()` method should require credentials.

## Concrete deliverables for `Coding-Agent`

- [ ] `src/specint/quality/dedup.py` — canonical hashing (title + author
      + duration bucket) plus SimHash-style near-duplicate detection
      over title/description bigrams. Exposes `deduplicate(records)` and
      `pairwise_similar(records, threshold)`.
- [ ] `src/specint/quality/language.py` — small character-trigram
      classifier for `{en, es, fr, de, it, pt, ja, zh, ar, ru}` trained
      inline from a static frequency table. Deterministic, offline, no
      network — mislabels are fine, we just want a signal.
- [ ] Extend `src/specint/quality/metrics.py` with two new components:
      `language_confidence` and `procedural_density` (number of
      `recipe_steps` normalised to a target of ~8 steps). Document the
      rationale as strictly as the existing components.
- [ ] `src/specint/sources/youtube_cc.py` — adapter for the YouTube Data
      API v3 `search` endpoint with `videoLicense=creativeCommon`.
      `parse()` must be fixture-testable; `search()` reads API key from
      `YOUTUBE_API_KEY` and yields **URLs + metadata only** (never
      media). Register in `REGISTRY`.
- [ ] `src/specint/compare/ablation.py` — run the harness under several
      preset `WEIGHTS` vectors (`baseline`, `no-license`, `steps-heavy`,
      `resolution-heavy`, `equal-weights`) and emit a
      `ReportBundle` under `reports/ablation-YYYY-MM-DD.json`. This
      operationalises the Comparison-First rule for any future scorer
      change.
- [ ] CLI: `python -m specint dedup --input <records.json>` and
      `python -m specint ablate --fixtures --output reports/ablation-*.json`.
- [ ] Tests: unit coverage for dedup, language detection, procedural
      density, YouTube adapter parse, ablation harness. All offline.
- [ ] CI: extend the workflow to (i) run the ablation on fixtures every
      build and (ii) upload the ablation JSON as an artifact.
- [ ] Refreshed baseline: `reports/baseline-2026-07-13.json` reflecting
      the new quality components (must not be silently regressed vs
      2026-06-20 without explanation).

## Risks the next reviewer should challenge

- A trigram language detector will mislabel very short titles. That is
  acceptable *only* if `language_confidence` decays with input length.
  Reject any implementation that returns a hard 1.0 on a 3-word title.
- SimHash on English titles alone will systematically collapse different
  recipes with identical stopwords ("How to make …"). Use bigrams and
  strip a modest stopword list; do not use raw unigrams.
- Any new YouTube adapter must be *behavior-tested against a checked-in
  fixture only*. A test that requires `YOUTUBE_API_KEY` in CI fails the
  offline-tests hard constraint.
- The ablation harness must NOT mutate the shared `WEIGHTS` dict — it
  must accept a `weights` argument and remain a pure function.

## Out of scope today

- Frame extraction, media download, WARC iteration (all remain the same
  posture as 2026-06-20).
- Non-video "difficult domains" (surgery, sports, manufacturing). We
  refactor the abstractions so they generalise, but ship only the
  cooking-focused corpus today.
