## What the current baseline actually proves

Ranked mean-quality on `terms=[cooking, recipe]`, offline fixtures:

| Source        | n | n_license_clean | mean_quality |
| ------------- | - | --------------- | ------------ |
| wikimedia     | 2 | 2               | 0.62         |
| peertube      | 2 | 2               | 0.57         |
| common_crawl  | 1 | 0               | 0.53         |
| archive_org   | 3 | 2               | 0.36         |

That's not a scientific result — the fixtures are tiny (**8 records total**)
and were hand-crafted by the seed commit. The ranking will **rot silently**
the first time anyone edits an adapter, because CI only checks that the JSON
serialises. This is my first attack surface.

## Hypotheses under test today

> **H1 (Comparability rot).** Without a golden-file regression on the
> baseline report, a well-meaning refactor of *any* adapter can flip the
> source ranking without breaking a single test. Fixable in one PR.

> **H2 (Silent license leakage).** `common_crawl.py` unconditionally sets
> `License.UNKNOWN`, even when the *page* itself declares a license via
> `<link rel="license">` or the JSON-LD `license` field (which is a first-class
> `schema.org/CreativeWork` property). We are throwing away legally-clean
> recipe pages *and* over-counting UNKNOWN pages against `n_license_clean`.

> **H3 (Cross-source duplication).** Wikimedia files are re-indexed by
> Internet Archive (`opensource_movies` collection) and cross-federated to
> PeerTube via `framatube.org`. Without dedup the "total quality-weighted
> hours" our comparison harness reports is an over-count of unknown factor.
> Metadata-only dedup (title + duration + author + `duration_s` bucket)
> should collapse ≥5 % of records in a realistic 10k crawl.

> **H4 (Fuzz brittleness).** Every `parse()` assumes upstream types. A single
> Wikimedia response where `duration` is a JSON string ("312.4") crashes the
> pipeline. We need one property-style unit test per adapter that feeds
> malformed variants and asserts we degrade to `duration_s=None` instead of
> raising.

> **H5 (Adapter drift vs allowlist).** `AGENTS.md` lists `YouTube Data API
> videoLicense=creativeCommon` as an approved metadata-only source, but no
> adapter exists. This is a legitimate, allowlisted, high-yield source; the
> gap makes our comparison harness biased against sources with strong tail
> coverage.

## Attack list — ordered by leverage / cost

1. **[Ship today, cheap]** Cross-source dedup module
   (`src/specint/quality/dedup.py`) — pure function, canonicalises
   `(title_norm, duration_bucket, author_norm)` into a stable digest;
   `run_comparison` calls it before aggregating. Adds one column
   `n_after_dedup` to `BenchmarkResult` (backwards compatible: default 0).

2. **[Ship today, cheap]** JSON-LD `license` + `<link rel="license">`
   extraction for `common_crawl.py`. Any URL matching
   `creativecommons.org/licenses/(by|by-sa)/…` or
   `creativecommons.org/publicdomain/zero/…` upgrades the record from
   `UNKNOWN` to the corresponding `License` enum. Never upgrade to
   `RESTRICTED` from missing info.

3. **[Ship today, cheap]** Golden-file regression test that pins the source
   ranking of the baseline fixture set. Any adapter change that reshuffles
   `mean_quality > next-mean_quality` fails CI with a diff.

4. **[Ship today, cheap]** Fuzz-lite: one parametrised pytest per adapter
   with malformed variants (missing fields, wrong types, null instead of
   list). Asserts no exception, and every returned record still validates as
   `VideoRecord`.

5. **[Next PR, medium]** YouTube Data API metadata adapter, gated by
   `SPECINT_RUN_INTEGRATION=1` and by the presence of `YOUTUBE_API_KEY`
   secret. Adapter stores **only** `videoLicense=creativeCommon` records and
   never sets `media_url` (we do not redistribute YouTube-hosted media even
   under CC-BY).

6. **[Next PR, medium]** Web Data Commons `VideoObject` subset loader.
   Instead of crawling WARCs directly, ingest WDC's yearly N-Quads dumps for
   `schema.org/VideoObject` (Apache-2.0 licensed extraction; per-record
   license comes from the source page). Massive yield multiplier for the
   `common_crawl` slug at zero incremental crawl budget.

7. **[Next PR, medium]** Add `has_narration` and `procedural_density` scoring
   components:
   - `has_narration` : language field set AND `duration_s ≥ 30 s`.
   - `procedural_density` : `len(recipe_steps) / max(1, duration_s / 60)`.

8. **[Later, larger]** Frame-level near-dup detection for the eventual
   download-and-store phase. Track: MLT-Dedup (arxiv 2606.12215) for the
   candidate-retrieval design; the pHash + BK-tree pipeline for the CPU-only
   tier.

## Risks a reviewer must challenge

- **Golden-file lock-in.** If a *legitimate* adapter improvement shifts the
  ranking, the golden test will require a manual bump of
  `reports/baseline-2026-06-20.json`. This is intentional friction, not a
  bug — the point is to force a human diff.
- **Dedup false positives.** Two different chefs can post two different
  5-minute pasta videos with the same title. The current heuristic bucket
  duration to `round(duration_s/30)` and never collapses records from the
  *same source*; a diversity-preserving version is documented in
  `dedup.py`.
- **Common Crawl license upgrade.** We upgrade to `CC_BY_SA` only when the
  URL is an *exact CC canonical* URL; anything else stays `UNKNOWN`. This
  keeps us on the safe side of AGENTS.md constraint (1).
