## 2. Hypotheses under active attack

### H2. *Compliance debt is now a legal defect.*

The EU AI Act's copyright-and-TDM obligations (Article 53, GPAI Code of
Practice) became enforceable **on 2 August 2026** — three weeks before
this plan. Any GPAI-adjacent training corpus we hand off must be able to
prove, per record, that at the *time of collection* the source respected
`robots.txt`, `ai.txt`, and TDMRep (`/.well-known/tdmrep.json` or the
`TDM-Reservation` HTTP header). Silence-means-permission for TDMRep,
silence-means-refusal for `ai.txt` — we must resolve both correctly.
Today the repo captures **none** of these signals. This is a P0.

### H3. *Duplication kills the "yield" axis of every benchmark.*

Wikimedia videos are re-mirrored on Internet Archive. Recipe pages
re-embed the same YouTube/Vimeo/Bilibili clip across a dozen food blogs.
Without dedup, our `n_records` and `total_duration_s` numbers are
optimistic by an unknown factor and cross-source comparison is
meaningless. MLT-Dedup (KDD '26) and the SVD benchmark motivate a
multi-level fingerprint: cheap URL/title shingles first, perceptual
video-hash later (only for records we actually download).

### H4. *Metadata quality signals are under-weighted for procedural video.*

Current scorer weights are `license 0.35 / duration 0.15 / resolution
0.20 / text_density 0.15 / has_steps 0.15`. It has no signal for:

- **aspect ratio** (16:9 == cooking-show framing; 9:16 == TikTok-style
  vertical shorts, which are worse for long-horizon world modeling);
- **audio_present** (recipe voice-over is the densest source of natural
  language↔action grounding we have);
- **cooking verb density** (chop, stir, whisk, sauté, simmer, fold …) in
  title+description+recipe_steps — a cheap procedural-ness prior;
- **shot-cut density proxy** (mean duration between JSON-LD `Clip` /
  `hasPart` markers, or between VTT cue times) — heavy edits usually
  mean commercial-style cooking shows, low cuts mean full-take
  procedural footage.

We should build these as *pure functions of metadata* and A/B them
against the June 20 baseline before touching weights.

### H5. *We're missing two allowlist sources that Coding-Agent has *permission* for but hasn't built.*

- **YouTube Data API v3, `videoLicense=creativeCommon`.** AGENTS.md
  explicitly allows metadata-only harvest of CC-BY YouTube listings. Not
  built. This is the largest single legal yield we're leaving on the
  table.
- **PeerTube federation walk.** Today's adapter takes a single instance
  URL. PeerTube's whole point is federation; a directory (e.g.
  `sepia-search.tv` API) points at hundreds of instances, each with
  per-video licenses. Not built.

### H6. *Provenance is a string, not a proof.*

`Provenance.extractor_git` is hard-coded to `"dev"` and there is no hash
of the raw upstream payload. If a Wikimedia record ever changes upstream
(licence re-tagging, deletion), we cannot prove which version we saw.
C2PA §9.2.5 (`c2pa.hash.collection.data`) is the industry direction; we
don't need a full C2PA signer today, but we do need a **content-addressed
raw-payload hash** and the real git SHA on every record.

## 3. Concrete deliverables for `Coding-Agent`

Priority order (P0 first). Each item **must** produce a benchmark row so
we can measure it.

### P0 — Legal / provenance hardening

- [ ] `src/specint/compliance/rights.py`
  - `RightsSignal` dataclass: `robots_allowed: bool | None`,
    `tdmrep: Literal["reserved","allowed","absent"]`,
    `ai_txt: dict[str, bool] | None`, `fetched_at`, `source_url`.
  - Pure `parse_robots(text, agent="specint")`,
    `parse_tdmrep_json(text)`, `parse_ai_txt(text)`; live fetcher
    behind `SPECINT_RUN_INTEGRATION`.
  - Fixture suite: `tests/fixtures/rights/{robots.txt, tdmrep.json,
    ai.txt}` for each of the 5 allowlisted sources.
- [ ] Extend `Provenance` with `raw_sha256: str` and
    `rights: RightsSignal | None`; update `db_structured.md`.
- [ ] Replace `extractor_git="dev"` with a real short SHA
    (`subprocess`-free helper reading `.git/HEAD` + `.git/refs`, with
    graceful `"unknown"` fallback for detached tarballs).
- [ ] CI gate: fail if any record in the fixture e2e run has
    `raw_sha256 == ""` or `rights is None`.

### P1 — Deduplication (offline, metadata-only)

- [ ] `src/specint/dedupe/urlhash.py`
  - `canonical_url(url)` — lowercase host, strip tracking params, drop
    trailing slash, resolve `youtube.com/watch?v=` vs `youtu.be/`.
  - `title_shingles(title, k=5)` + Jaccard.
  - `merge_records(records, threshold=0.85)` returning a
    `list[VideoRecord]` with a `.provenance.query` that lists all
    merged source ids.
- [ ] Harness change: after per-source aggregation, run a
    cross-source dedup pass and emit a *third* summary row per
    query, `source="__deduped__"`. Do not modify per-source rows.
- [ ] Benchmark expectation: `__deduped__.n_records` should be
    `<= __total__.n_records`; if it's equal on every fixture, the
    dedup is degenerate → add adversarial fixtures.

### P2 — Two new legal sources

- [ ] `src/specint/sources/youtube_cc.py`
  - Uses YouTube Data API v3 `search.list` with
    `videoLicense=creativeCommon&type=video&part=snippet`.
  - **Never** downloads media; `media_url=None` always. `url` is the
    `watch?v=<id>` page. `license=CC_BY` iff API returns CC.
  - Requires `YOUTUBE_API_KEY` env; unit tests use a checked-in
    fixture JSON, integration tests gated on `SPECINT_RUN_INTEGRATION`.
- [ ] `src/specint/sources/peertube_federation.py`
  - Ships with a *seed* instance list in `data/peertube_instances.txt`

  - `search(query)` fans out over instances with a per-instance
    concurrency cap, aggregates results, dedupes by ActivityPub actor

  - Unit test uses fixtures for 2 instances; integration test hits

## 5. Risks a reviewer should challenge

1. **Cooking-verb keyword lists over-fit English recipe blogs.** We
   should measure recall on a held-out set of non-English recipe pages
   before promoting the signal.
2. **PeerTube federation dedup by actor id misses re-uploads by a
   different account.** We accept this until video-hash lands (P1
   planned in a future sprint).
3. **YouTube CC listings routinely mis-declare licence** — the API
   returns `creativeCommon` for videos whose description contradicts
   it. We must set `License.UNKNOWN` (never `CC_BY`) unless the
   `contentDetails.licensedContent` field agrees; add a fixture that
   exercises this contradiction.
4. **Benchmark-regression gate at 0.05 absolute is arbitrary.** Once
   we have >20 fixture records per source, replace with a per-source
   bootstrap CI.
5. **The `hasPart` shot-density signal is trivially game-able.**
   Recipe-blog SEO plugins inject fake `hasPart` blocks. Cross-check
   against `Clip.startOffset` monotonicity before scoring.
