# Adversarial-Agent Plan — 2026-09-11

> Prior plan under attack: `docs/plan-2026-06-20.md`. Baseline under
> attack: `reports/baseline-2026-06-20.json`.

## Executive summary

The seed pipeline (June 2026) shipped four adapters, a metadata-only
quality scorer, a comparison harness, and a first baseline. Since then
the field has moved: SolarWM, Cosmos-Predict2.5, Sekai2 all released
open, *provenance-first*, multi-stage data engines with per-stage
retention logging; MLT-Dedup (KDD 2026) shows web-scale deduplication is
now table stakes; Ego2World reframes evaluation from "hours collected"
to "executable belief-state coverage". Our baseline has **three
measurable defects** that today's plan attacks head-on:

1. **Dedup is a no-op.** The same Wikimedia video mirrored on Internet
   Archive is counted twice in `__total__`. See
   `docs/artifacts/2026-09-11-mlt-dedup-maze.md`.
2. **License classification is heuristic and untested at boundaries.**
   Two-character differences in a URL (`/by/` vs `/by-nd/`) currently
   flip a record between `CC_BY` and `RESTRICTED` with no golden test.
3. **Tests do not enforce their own offline invariant.** Nothing stops
   a future adapter from silently calling `httpx.Client.get()` inside a
   supposedly-offline unit test; CI would flake, not fail.

Plus one structural gap:

4. **No frontier-domain coverage plan.** The seed plan is 100% cooking.
   The mission (AGENTS.md) is *"generalize to other difficult video
   domains"*. We must at least prove the abstractions generalize by
   registering a second domain (surgery, lab work, or manufacturing)
   before the current cooking-specific heuristics ossify.

## Hypotheses under test

- **H2 (dedup).** Cross-source URL-canonical dedup will collapse
  ≥ 15% of the `__total__` row today, and ≥ 40% once perceptual hashes
  are added. If not, our licenses skew independent enough that dedup
  is a lower priority than we thought — either result is informative.
- **H3 (license golden test).** A checked-in golden table of `(source,
  raw_license_string, expected_License)` will catch at least one
  regression in the current heuristics for either `wikimedia` or
  `archive_org` on the first CI run. If it passes cleanly, we know our
  seed heuristics are stronger than expected.
- **H4 (offline enforcement).** An autouse `no_network` pytest fixture
  that monkeypatches `httpx.Client.send` will break at least one test
  that currently "happens to work" only because upstream isn't called.
  If it doesn't, our source/parse split is cleaner than expected.
- **H5 (rejection logging beats retention counting).** Recording
  `n_dropped_by_stage` in `BenchmarkResult` gives a strictly stronger
  signal than `n_records` alone; specifically, we predict `wikimedia`
  will show a large drop at the "wrong mime type" stage that today is
  invisible.
- **H6 (procedural density > text density).** Replacing
  `text_density` with `procedural_density` (unique verb count in
  `recipe_steps` clamped to [0,1]) will re-rank sources: PeerTube's
  chatty descriptions should lose value while Common Crawl's recipe
  step-lists should gain. If this doesn't happen, our fixtures are too
  small to distinguish and we should expand them first.

## Adversarial questions to attack today

1. **Why is our baseline `__total__.mean_quality` 0.499 with only 8
   records?** Small samples mean the score is noise. Either grow the
   fixtures or switch to a bounded confidence interval when there are
   fewer than ~30 samples per source.
2. **What stops a `License.UNKNOWN` record from ending up in a training
   corpus downstream?** Nothing in code. This is a policy documented in
   AGENTS.md — we should turn it into a hard invariant checked in CI.
3. **How does the pipeline behave when an upstream adapter starts
   returning malformed JSON?** Today the whole harness raises
   uncaught. It should degrade to `n_records=0` for that source with a
   `notes` explaining why, so a single bad upstream can't blank a
   comparison run.
4. **Can Coding-Agent add a fifth source without touching the harness
   or the CLI?** They should be able to just drop a file into
   `src/specint/sources/` and register in `__init__.py`. We should have
   a test that asserts this by *dynamically* iterating `REGISTRY`
   rather than hardcoding source names anywhere else.
5. **Are we accidentally generalisable?** Try registering a
   `wikimedia_surgery` variant (same adapter, different query terms)
   to prove the abstractions carry to a non-cooking domain. If it
   requires code changes, the abstractions are wrong.

## Out of scope today

- Any live network I/O in tests (the offline invariant is being made
  stricter, not weaker).
- Downloading video media. We remain URL + metadata only.
- Building an actual embedding-based dedup index — the exact-match
  URL-canonical tier is sufficient to invalidate H2 and to justify (or
  refute) the heavier tier.

## Risks the next reviewer should challenge

- The new `plan-summary-updated` pre-commit hook is a local hook and
  therefore only runs when developers install pre-commit. We should
  mirror it as a CI job.
- The Hypothesis property tests must not accidentally reach the
  network; they operate purely on constructed `VideoRecord` instances
  (see conftest network-block fixture).
- The golden license table encodes today's understanding of
  MediaWiki's `LicenseShortName` values; if Wikimedia changes its
  convention, our test will lag reality. Add a comment linking to the
  authoritative page for future auditors.
- Adding Python 3.13 to CI can surface a Pydantic v2 / typing
  regression. Acceptable — better to know now.
