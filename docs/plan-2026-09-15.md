# Adversarial-Agent Plan — 2026-09-15

## Meta-observation: the merge queue is the bottleneck

There are 40+ prior draft PRs from the daily automation loop, all in `DRAFT`
against `main`, and only PR #1 (bootstrap) has ever landed. Every subsequent
Adversarial-Agent plan and Coding-Agent implementation reruns from the same
2026-06-20 base; ideas are being re-derived, not compounded. **This means
the highest-leverage adversarial intervention today is not "propose more
hypotheses" — it is to lower the cost of merging one.**

Concretely, PRs #43–#45 (the last two Coding-Agent + Adversarial-Agent
pairs) each touch 10–14 files and cross-cut licensing, quality scoring,
CLI, and new sources. Reviewers reasonably stall on that shape. Today's
plan therefore ships two things in parallel:

1. **A merge-order sub-plan** (§ Merge order) — a linearized sequence of
   ≤ 4-file PRs that a reviewer can land one at a time without stacking
   risk, drawn from the accumulated ideation across PRs #29–#45.
2. **Strictly-additive adversarial hypotheses** (§ Hypotheses H7–H10) that
   *were not* on yesterday's plan (PR #44) and that attack failure modes
   the existing test suite does not cover.

## Hypothesis under test

> **H7.** The offline fixture harness has never been stressed by *malformed*
> upstream payloads. Real Common Crawl JSON-LD in the wild frequently
> contains: (a) `@type` as list-of-strings including confusables like
> `"VideoObject "` with trailing whitespace, (b) recursive `@graph` cycles,
> (c) non-dict entries in `recipeInstructions`, and (d) `duration` values
> that are unquoted numbers. `parse_recipe_html` will silently drop these
> records or, in the cycle case, hang. A `hypothesis`-style fuzz suite
> should surface at least one of these paths as a bug today.

> **H8.** The pipeline double-counts cross-posts. Wikimedia Commons and
> Internet Archive both host a large subset of NASA / USGS / public-domain
> government video, and `commons.wikimedia.org/wiki/File:Foo.webm` and
> `archive.org/details/foo` can point at bit-identical media. `n_records`
> and `total_duration_s` in the current `BenchmarkResult` therefore
> over-report yield. A deterministic `dedup_key(record)` (media hash if
> known, else `(title, duration_s, author)` normalized) added to the
> harness would let us compute an honest yield metric. PR #43 proposed
> this — it should ship as its own tiny PR ahead of any new source.

> **H9.** `parse_recipe_html` reads only JSON-LD. Web Data Commons'
> statistics show ~30% of `schema.org/Recipe` markup on the open web is
> Microdata (`itemtype="http://schema.org/VideoObject"`) or RDFa. We are
> leaving ~30% of legally-clean recipe video yield on the table with a
> ~40-line parse change.

> **H10.** The quality scorer's `duration` component peaks at 5 min. For
> **procedural world-model training**, the actionable unit is a *shot*
> (contiguous camera position), not a whole video. A metadata-only signal
> — `duration_s / len(recipe_steps)` when `recipe_steps` is present —
> approximates "seconds per step" and better predicts the density of
> state-changes per minute of footage. This gives us a legal proxy for
> the InternVid PySceneDetect / Panda-70M shot-boundary filters *without*
> needing to download frames. See `docs/artifacts/2026-09-15-internvid-quality.md`.

## Merge order (linearized minimum-viable sequence)

The following queue is the shortest path from bootstrap to a corpus we
could actually train on. Each entry is scoped so that CI could land it
without touching the others' invariants.

| # | PR body (max ~4 files) | Blocks | Reason to land first |
| - | ---------------------- | ------ | -------------------- |
| 1 | `specint.licenses` central classifier (from PR #45) | 2, 3, 4 | Every other change grows the license matrix; central it now. |
| 2 | Cross-source `dedup_key` + `n_unique_records` on BenchmarkResult (from PR #43) | 3 | Without it, every yield metric is inflated. |
| 3 | `common_crawl` page-level license (from PR #45) + JSON-LD fuzz suite (H7, this plan) | — | Removes the "lying JSON-LD" laundering path. |
| 4 | New source: **Wikibooks Cookbook** (H-new, this plan) | 5 | Provides procedural *step text* pairable with Wikimedia video by title — first fully-legal (title, step-list, video) triple. |
| 5 | New source: **Sepia Search** (federated PeerTube, from PR #44) | — | Biggest single yield jump; no license drift risk. |
| 6 | `--yield-multiplier` benchmark axis (this plan) + Panda-70M-style desirability filter (H10 + artifact) | — | Turns quality from a scalar into a Pareto curve. |

Any PR that touches more than one of these buckets in a single diff is
adversarially rejected; that is exactly the shape #43–#45 have.

## Risks the next reviewer should challenge

1. **The merge-order plan is opinionated.** If the reviewer disagrees
   with "central licenses first, dedup second", the sequence collapses.
   Mitigation: each bucket is independently valuable; the ordering only
   matters if two-way merge conflicts materialize.
2. **H7's fuzz suite might not find a real bug in `parse_recipe_html`.**
   If it doesn't, it still becomes a regression net. Ship it either way
   and note the outcome in the PR body.
3. **H9's Microdata claim comes from an old (2019) Web Data Commons stats
   page**; the ratio may have shifted as JSON-LD adoption grew. Verify
   against a fresh WDC dump before writing the Microdata parser (do this
   in the corresponding Coding-Agent PR, not today).
4. **Wikibooks Cookbook is CC-BY-SA**, which propagates share-alike into
   any derived corpus. This is fine for research releases but must be
   flagged before we tell anyone this is "safe to fine-tune closed
   models on". Add an explicit `License.CC_BY_SA` gate in the harness
   before shipping the source adapter.
