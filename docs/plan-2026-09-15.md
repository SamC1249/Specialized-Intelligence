# Adversarial-Agent Plan — 2026-09-15

> Extends `docs/plan-2026-06-20.md`. Prior deliverables are green (see
> `reports/baseline-2026-06-20.json`); this plan attacks the weak spots
> the seed baseline exposed.

## Hypotheses under test

- **H2 (Dedup).** The `__total__` row in `baseline-2026-06-20.json`
  overstates *unique* yield: Wikimedia Commons and Internet Archive
  routinely mirror the same PD/CC-BY cooking clips, so the true unique
  count is strictly less than `sum(n_records)`. A deterministic
  cross-source dedup pass will show a non-trivial collision rate and a
  smaller-but-more-honest yield number.
- **H3 (Procedural density).** The current binary `has_steps` component
  under-uses the *text* signal we already extracted (title + description
  + step text). A continuous "cooking-imperative-verb density" score
  will re-rank the corpus in a way that correlates with human notion of
  "actually procedurally rich" while remaining metadata-only.
- **H4 (Scoring is not sacred).** Our seed weight vector is one point in
  a large space. A first ablation across ≥3 named profiles
  (`balanced`, `license_first`, `procedural_first`) will show that the
  ordering of sources depends on the profile — meaning "which source is
  best" is not well-defined until we commit to a profile.
- **H5 (English-only ceiling).** All seed terms today are English. A
  multilingual seed catalog (es/fr/de/it/ja/zh + en) is a prerequisite
  for internet-scale yield; without it we systematically ignore the
  non-anglophone cooking web.
- **H6 (Provenance is only as good as the SHA).** Every record's
  `provenance.extractor_git` is currently the literal string `"dev"`,
  making it impossible to reproduce a specific extraction from an old
  report. We should resolve the actual repo SHA once per process.
- **H7 (YouTube CC-BY listings are non-empty).** The allowlist in
  `AGENTS.md` includes YouTube's `videoLicense=creativeCommon` filter,
  but no adapter exists. A metadata-only parser (URL + title + author
  + duration, no media download) is inside our legal envelope and will
  meaningfully expand yield.

## Out of scope today

- Actually pulling YouTube result pages in CI (integration only).
- Any frame-level quality scoring (still metadata-only).
- Fuzzy title matching beyond ASCII-fold + lowercase — real MinHash /
  simhash is a future PR.

## Risks the next reviewer should challenge

- The imperative-verb lexicon is English-only for now; scoring rich
  Japanese cooking descriptions will be systematically under-weighted.
  Document as a known bias and open follow-up.
- `current_git_sha()` will fall back to `"dev"` when the checkout is
  detached or in CI shallow-clones — verify the CI job runs
  `fetch-depth: 0` before we start depending on the SHA for
  reproducibility.
- Dedup fingerprint uses `duration_bucket_10s`; recipes with unknown
  duration collapse into one big bucket and will over-collide. Guard
  by requiring `duration_s is not None` for the duration key
  contribution.
