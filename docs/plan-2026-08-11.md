## Where the current design is weakest — attack list

1. **Yield is imaginary.** Every "which source is best" claim rests on
   handfuls of fixture records. We need order-of-magnitude yield
   estimates from real listing APIs (not media downloads) before we can
   even prioritise engineering effort.
2. **Quality is unfalsifiable.** `WEIGHTS` in `quality/metrics.py` were
   hand-picked. There is no held-out label set, so any change to
   weights that raises the score is self-congratulatory. We need a
   small human-labelled gold set (~50 records with `usefulness_for_worldmodel`
   ratings) to fit and validate weights instead of guessing.
3. **License classification is regex-shaped.** `_coerce_license` in
   wikimedia does substring matching that will silently *upgrade*
   `CC-BY-NC-SA` to `CC_BY_SA` if the `-NC-` check misses. We need a
   test matrix of ~30 license strings covering all Wikimedia/Archive/
   PeerTube variants, including edge cases (multi-license OR clauses,
   trailing "4.0 International", localized strings).
4. **Cross-source dedup is missing.** The same Blender Foundation short
   film is on Wikimedia, Archive.org, and PeerTube. Without a dedup
   pass, aggregate metrics double-count. Cheap fix: normalise
   `(sha256(title.lower()), round(duration_s, -1))` as a soft key.
5. **`RESTRICTED` masquerading as `UNKNOWN`.** Coding-Agent already
   splits these enum values, but the adapters over-index on
   `UNKNOWN` (Common Crawl always returns `UNKNOWN`). A page-level
   license classifier is required so that "we could not tell" and "we
   determined it is not redistributable" are not conflated.
6. **The Common Crawl path is upside-down.** Instead of iterating WARCs
   ourselves, we should consume **Web Data Commons (WDC)** schema.org
   subsets which already extract `schema.org/Recipe` + nested
   `VideoObject` from Common Crawl at ~4.5M URLs / ~42K hosts per
   release. This is arguably 100–1000× more efficient than the current
   stub. See `docs/artifacts/2026-08-11-common-crawl-vs-wdc.md`.
7. **PeerTube coverage is hard-coded.** Federated discovery via
   `sepiasearch.org/api/v1/search/videos` (same schema, no auth,
   supports `licenceOneOf[]`) reaches the whole federation in one
   query. Estimated 5–10× yield vs polling 3 instances.
8. **YouTube-CC filter is a stub.** The legal allowlist explicitly
   permits `videoLicense=creativeCommon` listings for URL + metadata
   (no download). Coding-Agent has not implemented it. This is likely
   the single largest legal video-metadata pool for cooking.
9. **Domain-generalization is untested.** AGENTS.md mission is
   explicitly not just cooking. We have zero evidence the pipeline
   ports to surgery, lab work, or manufacturing videos. Ship a
   generalization smoke test as a second `SourceQuery` today.
10. **No network isolation guard.** `pytest` currently *could* hit the
    internet if someone forgot to use a fixture. AGENTS.md constraint
    #4 says tests are offline; we should *enforce* that with
    `pytest-socket` so any accidental live call fails loudly in CI.

## Hypotheses under test (H2–H7)

- **H2 (yield).** SepiaSearch + WDC-Recipe together deliver ≥ 10×
  more license-clean cooking-video records per crawl-day than the
  current 4-adapter mix, at equal or better `p50_quality`.
- **H3 (license precision).** A property-based license-classifier
  test matrix will reveal ≥ 3 false-positive substring bugs in the
  current adapters (predicted especially in Wikimedia + Archive.org).
- **H4 (dedup lift).** A cross-source dedup key removes 5–15 % of
  records from the aggregated pool, and the deduplicated `mean_quality`
  is *higher* than the naive pool (since duplicates skew toward
  low-metadata mirror copies).
- **H5 (generalization).** Swapping `terms=["surgery", "endoscopic"]`
  in the same harness yields non-zero records from ≥ 2 sources without
  code changes; if it does not, our pipeline is cooking-specific and
  the mission statement is aspirational.
- **H6 (procedural density beats resolution).** A new quality
  component `procedural_density = min(1, n_recipe_steps /
  max(1, duration_min))` will out-predict `resolution` as a proxy for
  world-model usefulness on a tiny human-labelled gold set
  (deliverable: 50 records with 1–5 usefulness scores).
- **H7 (gold-set survives Coding-Agent).** Weights fitted on gold set
  produce a comparison report where the *ranking* of the 4 current
  sources is stable under 5 leave-one-out perturbations of the gold
  labels. If not, our quality score is over-fit noise.

## Concrete deliverables for the next Coding-Agent shift

Priority-ordered so partial completion is still useful.

### P0 — Guardrails so nothing regresses silently

- [ ] `pytest-socket` added to `[dev]`; `conftest.py` calls
      `disable_socket()`. Any test that *needs* network must explicitly
      `@pytest.mark.integration` and be gated by
      `SPECINT_RUN_INTEGRATION=1`. (Partially shipped in this PR — see
      "What Adversarial-Agent shipped alongside this plan" below.)
- [ ] `tests/test_schema_drift.py` — assert that every column in
      `db_structured.md` `VideoRecord` table corresponds to a field on
      `records.VideoRecord`, and vice versa. Prevents the doc and the
      Pydantic model drifting. (Partially shipped in this PR.)
- [ ] `tests/test_baseline_regression.py` — re-run
      `run_comparison` against the checked-in fixtures and assert the
      resulting report is byte-identical (modulo `fetched_at`) to
      `reports/baseline-2026-06-20.json`. This makes accidental
      quality-scorer changes a CI failure. (Partially shipped.)

### P1 — Kill the two biggest source-yield deficits

- [ ] `src/specint/sources/sepia.py` — SepiaSearch adapter, reusing
      PeerTube's `_peertube_license`. Fixture: `tests/fixtures/sepia/
      search_cooking.json`. Add to `REGISTRY`. Aim: replace `peertube`
      as the "federated" default, keep `peertube` for per-instance
      benchmarking.
- [ ] `src/specint/sources/wdc_recipe.py` — Web Data Commons
      recipe-subset adapter. Consumes an **offline** WDC N-Quads chunk
      (fixture) and emits `VideoRecord` for every `Recipe` node that
      nests a `VideoObject`. Do not depend on live WDC downloads in
      unit tests; the offline chunk lives under `tests/fixtures/
      wdc_recipe/sample.nq`. Live download is a separate opt-in path.
- [ ] `src/specint/sources/youtube_cc.py` — YouTube Data API v3
      adapter that only queries `videoLicense=creativeCommon` and
      stores metadata only (no `media_url`). Requires `YT_API_KEY` env
      var; refuses to run without it. Fixture: `tests/fixtures/
      youtube_cc/search_cooking.json`.

### P2 — Sharpen quality signal

- [ ] `data/gold/cooking-usefulness-v0.jsonl` — 50 hand-labelled
      records (`record_id`, `usefulness_1_5`, `notes`). Half from
      wikimedia + half from a mix of the other three sources.
      Adversarial-Agent will draft the labelling rubric in the next
      plan; Coding-Agent should implement `specint eval --gold
      data/gold/...json` that reports Spearman(quality_score,
      usefulness_1_5) and per-component correlations.
- [ ] `src/specint/quality/metrics.py` — add `procedural_density`
      component (H6). Keep weights the same for now; the eval CLI will
      report whether the component correlates with the gold labels.
- [ ] Cross-source dedup pass in `compare/harness.py` behind
      `--dedup` flag; emit a `n_deduplicated` field on `BenchmarkResult`.
      Update `db_structured.md` and the drift test.

### P3 — Generalization proof-of-life

- [ ] `src/specint/cli.py` — accept `--domain cooking|surgery|
      lab|manufacturing` as sugar for a curated `SourceQuery`. Ship a
      `reports/generalization-2026-08-11.json` produced by running the
      harness against all four domains against fixtures. If a domain
      returns 0 records for every source, log it as a known gap in the
      next plan.

## Out of scope for this shift

- Actual bulk video download or frame extraction. Metadata + URL only.
- Any source that requires paid credentials.
- Multi-lingual search terms; English is still the seed.
- Distributed crawling; single-process is still fine.

## Risks the Coding-Agent reviewer should challenge

- Building a WDC adapter locks us to a corpus that is refreshed only
  ~yearly. If we depend on it exclusively, our data gets stale. It
  should complement, not replace, live source adapters.
- SepiaSearch is a single point of failure; if it goes down we lose
  federated discovery. Keep the per-instance PeerTube adapter as a
  fallback.
- YouTube's `videoLicense=creativeCommon` filter is known to
  mis-classify some uploads. We must treat YouTube-CC metadata as
  `License.CC_BY` **only after** re-checking each video's watch-page
  license badge. Ship that verification step in the same PR as the
  adapter.
- Gold-set labelling is subjective. Two labellers minimum; log
  inter-rater agreement (Cohen's κ) alongside the gold file.
