# Adversarial-Agent Plan — 2026-07-18

> Continues the seed plan of 2026-06-20. All bootstrap deliverables shipped.
> This plan attacks the *follow-ups* the seed plan flagged as risks: license
> classification robustness, multilingual coverage, cross-source duplication,
> and procedural-density heuristics — plus adds the first
> AGENTS.md-allowlisted source that requires an API key (YouTube Data API,
> filtered to `videoLicense=creativeCommon`).

## Hypothesis under test

> **H2.** The 2026-06-20 baseline overestimates yield because it treats the
> same recipe hosted on multiple upstreams (e.g. a Wikimedia Commons video
> mirrored on Internet Archive) as independent samples. A canonical,
> content-addressed dedupe layer will shrink `n_records`, and a Pareto view
> `(license_clean × procedural_density × resolution × unique-after-dedupe)`
> will produce a stricter and more informative ranking than mean quality
> alone.

> **H3.** Metadata-only *procedural density* — normalized count of imperative
> verbs, numeric quantities, and temporal expressions in
> `title + description + recipe_steps` — is a better proxy for downstream
> world-modeling usefulness than raw text length, because it isolates
> "action per token" rather than rewarding marketing prose.

> **H4.** A cheap language detector run on the record's title + description
> is sufficient to lift `record.language` from ~30% populated to >95% on
> our fixtures without a heavyweight dependency (e.g. langdetect), so we
> can meaningfully add a multilingual axis to the harness without touching
> our zero-network guarantee.

## Adversarial questions to attack today

1. **Cross-source overlap.** Given the same query, how many records across
   `{wikimedia, archive_org, peertube, common_crawl, youtube_cc}` are the
   same underlying media? Prove it with a dedupe report on fixtures.
2. **License audit.** For each `License` value, count how many records
   carry a redistributable `media_url`. Any RESTRICTED record with a
   non-null `media_url` is a *bug* — surface it as a harness assertion.
3. **Procedural signal.** Design a metadata-only `procedural_density`
   scorer and confirm it separates "5-minute knife-skills tutorial with
   4 imperative steps" from "10-minute vlog with same word count" on our
   fixtures.
4. **Multilingual.** Populate `language` when missing. Measure
   language-coverage per source and add it to the JSON report.
5. **New source.** Add `youtube_cc` (metadata-only, Data API v3 with
   `videoLicense=creativeCommon`), fixture-driven parser, live path gated
   behind `SPECINT_YOUTUBE_API_KEY`. Zero media download.
6. **Comparison discipline.** New baseline JSON must be committed and
   *strictly comparable* to the 2026-06-20 baseline — same fixtures, same
   query, delta reported in the plan summary.

## Out of scope today

- Downloading media / frame extraction.
- Distributed crawl.
- Non-English recipe-step *parsing* (we only detect the record's language;
  extractors still ship English-first heuristics).
- Actual live YouTube calls in CI (fixture-only; live path is gated).

## Risks the next reviewer should challenge

- **False dedup merges.** Title-only matching will collide on generic
  names like "Pancakes". Dedupe MUST require at least two signals
  (media_url hash OR (title + author) OR (title + duration ±5%)).
- **Language leakage.** The heuristic detector is biased toward Latin
  scripts; declare it as such and *never* discard records that fail to
  classify — leave `language=None`.
- **Procedural density gaming.** Recipe farms stuff step lists to game
  SEO. Cap the component at 1.0 well before pathological lengths and
  penalize copy-pasted duplicate steps.
- **YouTube ToS.** We only store title/description/URL/license metadata;
  no `contentDetails` beyond duration; no media pull. The record's
  `media_url` is always `None` for `youtube_cc`.
